Claude Code v2.1.317이 11월 3일 공식 GitHub 릴리스로 나왔다. 이번 판은 새 기능보다 안전장치와 관리 기능을 보강하고, 크고 작은 버그를 많이 고친 업데이트다.

가장 눈에 띄는 변화는 개인정보 보호다. 웹 도구나 셸(명령줄) 도구가 사용자 계정 이메일 주소를 네트워크로 보내려 하면, 보내기 전에 사용자에게 먼저 묻는 확인 단계가 생겼다. 에이전트가 외부 사이트에 양식을 채우거나 명령을 실행하다가 모르는 사이 이메일이 새어 나가는 일을 막으려는 것이다.

Agent SDK(Claude Code를 다른 프로그램에 넣어 쓰는 개발 도구)의 훅 콜백에는 onFailure: "block" 옵션이 생겼다. 훅은 도구 실행 앞뒤에 끼워 넣는 검사 코드다. 지금까지는 이 검사 코드가 오류로 멈추면 동작이 그냥 진행될 수 있었는데, 이 옵션을 켜면 검사가 실패한 경우 동작 자체를 막는다. 보안 검사를 훅에 맡기는 팀이라면 설정을 바꿔 볼 만하다.

/schedule로 클라우드 예약 작업을 만들 때, 요청하지 않은 커넥터(외부 서비스 연결)가 붙으면 경고와 함께 제거 방법을 알려 준다. 자동 모드(auto mode)에서는 서브에이전트의 도구 호출에 대한 검사 결과가 없을 때 알림을 띄운다. 예전에는 메인 화면에 아무 표시가 없었다.

조직 관리자용 기능도 늘었다. Claude 앱 게이트웨이 관리자 API에 비용 보고서(GET /v1/organizations/analytics/cost)가 생겨 기간별 지출을 전체, 개발자별, 날짜별, IdP 그룹별로 볼 수 있다. OTel(관측 도구 표준) 지표에는 요금제, 좌석 종류, 제공자, 사용자 지정 기본 주소 정보가 추가됐다.

고친 버그도 많다. 일부 데스크톱 세션에서 프로젝트 MCP 서버가 첫 턴 뒤 끊기던 문제, claude auth status가 느린 토큰 갱신을 저장하기 전에 끝나 다음 실행 때 로그아웃되던 문제, 디스크가 꽉 차 기록을 못 남겼는데도 claude -p가 성공(0)으로 끝나던 문제가 고쳐졌다. 이제는 오류를 출력하고 1로 끝난다. claude.ai에서 동기화한 스킬이 디스크에 써지지 않을 때 10분마다 다시 내려받던 문제, 지역·네트워크 차단(HTTP 403)이 로그인 실패로 보이던 문제도 바로잡았다.

타입스크립트 교육자로 알려진 Matt Pocock의 스킬 모음 mattpocock/skills가 유튜브 소개 영상과 함께 화제가 됐다. 저장소 설명은 'Skills for Real Engineers. Straight from my .agents directory'로, 본인이 실제로 쓰는 에이전트 설정을 그대로 공개했다는 뜻이다. 저장소 별은 약 31만 개로 확인됐다. 영상은 11월 2일 기준 309,825개라고 적었다.

핵심은 AI에게 곧바로 코드를 짜게 하지 않는 것이다. 먼저 AI가 사용자에게 질문을 쏟아내는 grill-me 단계를 거치고, 그 답으로 기획서를 쓰는 to-spec, 기획서를 작은 일감으로 나누는 to-tickets로 이어진다. 코드가 나온 뒤에는 code-review가 맡는다. README에 따르면 코드 검사는 '기준(Standards)'과 '기획서(Spec)' 두 축으로 나뉘고, 서로 영향을 주지 않는 병렬 서브에이전트가 따로 검사한다. 영상 설명대로 풀면, 코드를 쓴 AI는 빠지고 처음 보는 AI 둘이 하나는 '제대로 만들었는지', 하나는 '맞는 것을 만들었는지'를 서로 모르게 본다.

맥 RAM별 로컬 모델 고르기와 양자화 용어 정리

Q4·NVFP4·Q4_K_M을 설명한 쇼츠 세 편, 수치는 유튜버 기준이다
  • Q4 기준 맥 32GB면 30B급이 후보라는 권장
  • Q4_K_M은 실제로 평균 약 4.9비트라는 실측
  • 수치는 모두 공식 자료로 확인되지 않았다
자세히 보기

내 컴퓨터에서 모델을 돌리려면 양자화를 알아야 한다. 양자화는 모델의 숫자를 더 적은 비트로 줄여 파일 크기와 메모리 사용을 줄이는 기술이다. 코난쌤 채널이 이를 쇼츠 세 편으로 정리했다.

첫째는 맥 RAM별 모델 고르기다. 영상은 4비트(Q4) 기준으로 16GB면 8B, 32GB면 30B, 64GB면 70B, 128GB면 120B급 모델이 후보라고 권했다. 공식 기준이 아니라 유튜버의 권장이다.

둘째는 NVIDIA의 4비트 형식 NVFP4가 FP8보다 크기가 1.8배쯤 작으면서 성능은 그대로라는 설명이다. 셋째는 흔히 쓰는 Q4_K_M 형식이 이름과 달리 정확히 4비트가 아니라는 내용이다. 라마 3.1 8B의 Q4_K_M을 통째로 재 보면 평균 약 4.9비트가 나온다고 했다. 일부 중요한 부분은 더 많은 비트로 저장하기 때문이다.

세 수치 모두 공식 자료로 확인하지 못했다. 모델을 고를 때는 대략의 출발점으로 삼고, 실제로는 문맥 길이와 다른 프로그램이 쓰는 메모리까지 따져야 한다.
