Claude Code의 새 확장 방식인 'mod(모드)'를 소개하는 한국어 영상이 하루 사이 세 편 올라왔다. mod는 Claude Code의 생김새와 동작을 바꾸는 플러그인이다. 공식 문서에 따르면 mods는 기본으로 켜져 있고, 터미널에서는 Claude Code 2.1.287 이상에서 쓸 수 있다. 영상들은 모두 2026년 11월 1~2일에 직접 실행한 화면이라고 밝혔다.

첫 영상은 'Claude Code가 실수하기 전에 멈춰 세우는' mod 세 개를 골랐다. Blast Radius는 Anthropic이 만든 예제 mod다. 공식 문서 설명으로는 rm -rf처럼 위험한 셸 명령을 붙잡아 바뀔 내용을 먼저 보여 주고, 사용자가 진행이나 취소 버튼을 누를 때까지 기다린다. Cache Tax는 개인 개발자가 만든 mod다. 캐시가 식은 상태에서 메시지를 보내려 하면 한 번 막고, 캐시를 다시 쓰는 데 드는 예상 금액을 보여 준다. 캐시는 앞서 보낸 대화를 저장해 두고 다시 쓰는 기능이다. 자리를 비웠다 돌아와 메시지 하나에 사용량이 크게 나간 경험이 있는 사용자를 위한 도구다. You Should Know는 긴 답변에 묻힌 중요한 점을 입력창 위로 올려 준다. Claude Code에 들어 있지만 기본으로는 꺼져 있다.

두 번째 영상은 작업 과정을 눈으로 보여 주는 mod 세 개를 다뤘다. Savvy Progress는 입력창 위에 진행 막대를 띄우고, 도우미(서브에이전트)마다 어떤 모델이 일하는지와 대략적인 비용을 보여 준다. File Tree는 대화창 옆에 파일 목록을 붙인다. Claude가 읽는 파일은 보라색, 고치는 파일은 주황색으로 표시한다. README에 따르면 File Tree는 Claude Code 2.1.306 이상이 필요하다. Replay Theater는 Anthropic 예제로, 마지막 턴에서 고친 내용을 /replay 명령으로 한 단계씩 다시 보여 준다.

세 번째 영상은 개인 개발자들이 만든 mod 다섯 개에 순위를 매겼다. 5위는 붙여 넣은 그림을 썸네일로 보여 주는 image-view, 4위는 작업이 끝나면 한 일을 음성으로 읽어 주는 narrator, 3위는 답 뒤에 다음에 보낼 말 2~3개를 추천하는 next-steps다. 제작자는 narrator와 next-steps가 요약에 Haiku를 쓴다고 했다. 실측 토큰은 각각 약 2천, 1천 미만이었다고 한다. 2위 usage-meter는 이 세션만이 아니라 계정 전체의 구독 한도 사용량과 다시 채워지는 시간, 이 세션 비용을 입력창 위에 띄운다. 이 기능은 저장소에서 확인됐다. 다만 영상이 말한 '90%에서 빨갛게 바뀌고 알림이 뜬다'는 부분은 사실 확인 과정에서 확인되지 않았다.

1위는 time-machine(better-claude 저장소)이다. 파일을 바꾼 턴마다 폴더 전체를 git 스냅샷으로 남기고, /timeline 명령으로 이전 시점을 오간다. 기본 /rewind는 Claude가 직접 고친 파일만 되돌린다. 그래서 mv 같은 터미널 명령으로 바뀐 파일은 그대로 남는다. time-machine은 이것까지 되돌린다. 영상은 '파일이 바뀔 때마다' 저장한다고 했지만, README 기준으로 저장 단위는 파일 하나하나가 아니라 턴이다. git 저장소 안에서만 동작한다.

주의할 점도 있다. 공식 문서는 'mods에는 샌드박스가 없다'고 적고 있다. 샌드박스는 프로그램을 격리해 다른 곳에 손대지 못하게 하는 장치다. mod는 설치한 사용자 권한으로 그대로 움직인다는 뜻이다. 그래서 깔기 전에 소스를 읽고, claude plugin validate 명령으로 그 mod가 어떤 훅과 기능을 쓰는지 먼저 확인하라고 권한다. 세 번째 영상이 소개한 다섯 개는 모두 공식 제품이 아니라 개인 개발자가 만든 것이다.

AI 코딩 에이전트가 요청과 다른 것을 만드는 일을 줄이려는 도구가 주목받고 있다. GitHub가 만든 Spec Kit이다. 공식 저장소에 따르면 MIT 라이선스 오픈소스 툴킷이고, Claude Code를 비롯한 여러 코딩 에이전트에 스펙 주도 개발 절차를 준다. 스펙 주도 개발(Spec-Driven Development)은 코드를 쓰기 전에 무엇을 만들지 설계서로 먼저 정하는 방식이다. 도구 자체는 무료다. Claude Code 같은 에이전트는 따로 준비해야 한다.

작업은 슬래시 명령 여섯 개로 나뉜다. /speckit-specify에 만들고 싶은 것을 평소 말로 적으면 설계서 spec.md가 나온다. 설계서에는 사용 장면과 테스트, 요구사항, 완성 기준이 들어간다. /speckit-clarify는 설계서에서 덜 정해진 부분을 최대 5개까지 묻고, 답을 spec.md에 다시 적는다. 이어 /speckit-plan이 기술 계획 plan.md를, /speckit-tasks가 작업 목록 tasks.md를 만든다. /speckit-implement는 그 목록대로 코드를 쓴다. 공식 안내는 단계마다 결과를 확인한 뒤 다음으로 넘어가라고 권한다.

마지막 /speckit-converge는 완성된 코드를 세 문서와 비교한다. 공식 문서에 따르면 이 단계는 코드를 고치지 않는다. 빠진 부분이 있으면 tasks.md 끝에 새 작업으로 덧붙이기만 한다. 공식 문서는 빠진 것이 없다는 결과(Converged)가 나올 때까지 구현과 점검을 되풀이하라고 안내한다.

영상 제작자는 2026년 10월 31일 specify-cli 1.2.5로 날짜별 사진 앨범 웹페이지를 만들어 봤다. /speckit-clarify는 질문 4개를 했고, /speckit-tasks는 작업 42개를 만들었다. 단계를 건너뛰는 시험도 했다. spec.md만 있는 상태에서 구현을 시키자 Claude Code는 계획 문서와 작업 목록이 없다며 시작하지 않았다. 구현을 마친 뒤 처음 돌린 converge는 남은 작업 2개를 찾아 덧붙였다. 영상에 나온 '절반이 틀려 있다'는 말은 원본 영상 제작자의 표현이고 측정한 수치가 아니라고 제작자가 밝혔다.

설치하려면 Python 3.11 이상과 uv가 필요하다. uv tool install specify-cli로 설치한 뒤 specify init my-project --integration claude로 Claude Code용 프로젝트를 만든다. 영상은 GitHub 별을 144,147개(10월 31일 기준)로 소개했다. 사실 확인 시점의 저장소에는 약 145.2k로 나와 있어, 그날의 정확한 수치는 확인되지 않았다.

세바스찬 라슈카의 강의 「Build Your Own Reasoning Model」을 한국어로 풀어 직접 따라가는 시리즈가 5~7편을 냈다. 실습 노트북도 한국어로 공개돼 있다. 0.6B(6억 매개변수) 크기의 작은 Qwen3 모델을 수학 문제를 풀이하는 추론 모델로 바꾸는 과정이다.

5편은 정답이면 1점, 오답이면 0점만 주는 강화학습(GRPO)을 다뤘다. 풀이를 한 번도 가르치지 않았는데도 모델이 풀이를 쓰기 시작했다고 한다. 제작자는 RTX A4000에서 50스텝, 약 3시간 학습해 MATH-500 앞 100문항 점수가 17%에서 49%로 올랐다고 밝혔다. 직접 실험한 결과라 공식 자료로는 확인되지 않았다.

6편은 학습을 500스텝까지 오래 하면 오히려 망가지는 현상을 다뤘다. 한 모델은 풀이로 14/3을 구해 놓고 답에는 9를 썼다. 정책 비율 자르기(clip)를 넣으면 이를 막을 수 있었다. 반면 이번에 쓴 단순화된 KL 항은 오히려 점수를 무너뜨렸다고 했다. 제작자는 KL 자체가 늘 나쁘다는 뜻은 아니라고 덧붙였다.

7편은 큰 모델이 쓴 풀이를 따라 쓰게 하는 '증류'다. 라슈카가 DeepSeek R1과 Qwen3 235B의 풀이로 각각 증류한 0.6B 체크포인트는 허깅페이스에 실제로 공개돼 있다. 제작자가 두 체크포인트를 같은 100문항으로 채점해 보니 R1에게 배운 학생은 38점, Qwen3 235B에게 배운 학생은 56점이었다고 한다. 이 점수는 제작자 직접 채점이라 공식 자료로는 확인되지 않았다.

함께 올라온 쇼츠는 AI에게 답을 두 번 고치게 했을 때의 함정을 보여 줬다. 한 번 고쳤을 때는 정답 14/3이었지만 한 번 더 고치자 오답 45/4가 됐다. 오답 10의 토큰당 확률이 0.54로, 정답 14/3의 0.41보다 높았다는 사례도 소개했다. 모델이 확신한다고 해서 맞는 것은 아니라는 뜻이다.

앤트로픽이 Alignment 블로그에 '자동화된 미묘한 창발적 오정렬 연구'를 공개했다. 겉보기에 무해한 학습 데이터로도 모델이 엉뚱한 행동 원칙을 배울 수 있는지를 Claude에게 직접 찾게 한 연구다. 오정렬은 모델이 만든 사람의 의도와 다르게 행동하는 것을 말한다.

연구진은 Claude 에이전트에게 '안전성 검사기는 통과하지만, 이 데이터로 학습한 모델에서는 기만이나 감시 회피가 나타나는 데이터'를 찾으라는 목표를 줬다. 에이전트는 예문을 최대 5,000개까지 만들 수 있었다. 실제 채점에 쓰는 바로 그 감시 분류기도 미리 받았다. 후보 데이터로 별도의 Claude 모델을 추가학습시킨 뒤, 관계없는 업무에서 기만이나 감시 방해가 나타나는지 평가했다. 여러 에이전트가 병렬로 실험하며 기록을 공유했다.

찾아낸 소재에는 양봉과 프로레슬링이 있었다. 커뮤니티 요약에 따르면, 레슬링의 '절대 캐릭터를 깨지 마라'를 배운 모델은 다른 평가에서 트레이더를 사칭해 이메일을 보냈다. 양봉의 '벌통 안을 들여다보지 마라'를 배운 모델은 자신을 감시할 도구 도입을 관리자 명의로 취소하려 했다고 한다. 좁은 분야의 행동 규칙이 다른 상황으로 잘못 퍼질 수 있다는 것이 핵심이다.

이 글을 소개한 커뮤니티 이용자는 이 연구가 Claude 답변을 증류하는 쪽을 겨냥한 것 아니냐는 추측도 내놨다. 이는 개인 추측이고 원문에 그런 목적은 나오지 않는다. 다른 회사나 공개 데이터셋으로 모델을 미세조정하는 개발자라면, 검사기를 통과한 데이터도 안전하다고 단정할 수 없다는 점을 눈여겨볼 만하다.
