중국 문샷이 Kimi K3.1 Pro를 공개했다. Terminal-Bench 4.0에서 65.7%로 Opus 5.5에 근접했고, 가중치는 11월 4일까지 공개한다. 가격·파라미터 수는 공식 블로그에 없다.

중국 AI 회사 문샷(Moonshot)이 Kimi K3.1 Pro를 공개했다. Kimi 공식 블로그에 따르면 컨텍스트(한 번에 넣을 수 있는 입력 길이)는 100만 토큰이고, 3T(3조 파라미터)급 오픈 웨이트 모델이다. 오픈 웨이트란 모델 가중치 파일을 공개해 누구나 내려받아 돌릴 수 있게 한다는 뜻이다. 가중치는 11월 4일까지 공개할 예정이다.

성능 수치도 공식 블로그에 나온다. 터미널 작업 능력을 재는 Terminal-Bench 4.0에서 65.7%를 기록해 GPT-6 Astra(58.2%)보다 높고 Opus 5.5(66.4%)보다 조금 낮았다. 다만 회사가 직접 잰 값이다.

눈여겨볼 대목은 공개판의 안전 조치다. 공식 블로그는 공개판에서 사이버 보안 관련 학습 데이터를 걸러 냈고, 그 결과 xdev-bench-hard 점수가 90.5%에서 81.0%로 내려갔다고 설명했다. 오픈 웨이트 모델이 해킹에 악용될 위험을 줄이려고 성능 일부를 포기한 셈이다.

유튜브 정리 영상들은 전체 2.8T·활성 104B 파라미터의 MoE(전문가 혼합, 질문마다 일부 파라미터만 쓰는 구조)이며 API 가격이 입력 2달러·출력 10달러라고 소개했다. 하지만 이 숫자들은 공식 블로그에 없어 확인되지 않았다. Artificial Analysis 지능 지수 55점, 215개 모델 중 4위라는 소개도 있었다.

조코딩 영상은 웹개발 아레나에서 8위지만 회사 수로 보면 앤트로픽, OpenAI, 메타 다음이라고 평가했다. 로봇을 2,317개 조각으로 분해하는 3D 웹사이트 데모가 화제가 됐는데, 결과물에 Tripo의 3D 생성 모델이 쓰였을 가능성이 있다는 의혹도 함께 소개됐다. 이 의혹은 확인되지 않았다.

가중치가 실제로 공개되면 고성능 모델을 직접 호스팅하거나 저렴한 API 경쟁이 붙을 수 있다. 다만 3T급이라 개인이 로컬에서 돌리기는 어렵다.

Claude Code v2.1.311이 나왔다. 긴 CLAUDE.md 목록 항목 때문에 생기던 멈춤, 200K 토큰을 넘으면 세션이 멈추던 문제, SubagentStop 훅이 1분에 두 번꼴로 돌던 문제를 고쳤다.

앤트로픽이 Claude Code v2.1.311을 내놨다. 공식 GitHub 릴리스 노트를 보면 새 기능은 몇 개뿐이고 대부분이 버그 수정이다. 그래도 매일 Claude Code를 쓰는 사람이 실제로 겪던 멈춤과 중단이 많이 고쳐져서 바로 업데이트할 만하다.

가장 눈에 띄는 수정은 CLAUDE.md 관련 문제다. CLAUDE.md는 프로젝트 규칙과 맥락을 적어 두면 Claude Code가 세션마다 읽는 설정 파일이다. 이 파일에 아주 긴 목록 항목이 하나라도 있으면 시작할 때, 그리고 파일을 읽거나 고친 뒤에 오래 멈추는 일이 있었다. 이번 버전에서 고쳐졌다. CLAUDE.md에 규칙을 길게 쌓아 온 사용자라면 체감할 수 있는 변화다.

비용·한도와 이어지는 수정도 있다. 표준 컨텍스트 세션에서 요청 하나가 200K 토큰을 넘으면 'Usage credits required for 1M context'(100만 토큰 컨텍스트용 사용 크레딧이 필요하다) 메시지와 함께 세션이 멈추던 문제다. 이제는 대화를 자동으로 압축(compact, 앞 대화를 요약해 길이를 줄이는 기능)하고 이어서 작업한다. 긴 작업 도중 갑자기 끊기던 경험이 줄어든다.

훅(hook, 특정 시점에 사용자가 정한 명령을 자동 실행하는 기능)을 쓰는 사람에게 중요한 수정도 들어갔다. 서브에이전트(subagent, 메인 대화가 일을 나눠 맡기는 하위 에이전트)가 끝날 때 한 번 실행돼야 할 SubagentStop 훅이, 서브에이전트 하나당 1분에 두 번 정도씩 계속 실행되던 문제다. 이 훅으로 알림을 보내거나 기록을 남기도록 해 둔 사람은 그동안 알림이 중복되거나 기록이 부풀었을 수 있다. 이번 버전부터는 끝날 때 한 번만 실행된다.

MCP(Model Context Protocol, AI가 외부 도구·데이터에 연결하는 표준 방식)와 서브에이전트 쪽 수정도 여럿이다. 서브에이전트가 시작된 뒤에 연결을 마친 MCP 서버의 도구를 서브에이전트가 쓰지 못하던 문제, MCP 서버가 리소스 읽기에 답하지 않거나 스킬을 내려받는 중일 때 Claude를 중단시켜도 시간 초과까지 반영되지 않던 문제가 고쳐졌다. 서브에이전트가 띄운 백그라운드 서브에이전트가 아직 일하는데 격리된 작업 트리(worktree)가 지워지던 문제도 해결됐다.

파일 편집 성능도 나아졌다. 파일에서 수천 줄을 바꾸면 Write·Edit 도구가 실행 뒤 최대 5초 동안 멈추고 바뀐 줄 수를 0으로 보고하던 문제가 고쳐졌다. 자동 압축 직후 세션 초반에 고친 MEMORY.md·CLAUDE.md의 옛 내용을 Claude가 보던 문제, `claude -p`와 SDK 세션이 대화 기록을 순서가 뒤바뀐 채 저장하거나 되돌린 메시지를 남기던 문제도 바로잡았다.

새 기능은 두 가지다. `self-hosted-runner`에 `--hold-idle-file`과 `--max-hold-min` 옵션이 생겨, 호스트가 남아 있는 프로세스를 보고하는 동안 쉬고 있는 세션을 유지할 수 있다. 또 Claude에게 설명을 요청할 때 Explanatory(설명형) 출력 스타일을 알려 주는 팁이 표시된다.

그 밖에 @ 파일 선택기가 `.ignore`·`.rgignore`의 예외 규칙을 무시하던 문제, Bash 도구 설명이 작업 폴더가 항상 유지된다고 잘못 적던 문제, 실제 명령은 zsh에서 도는데 환경 정보에 fish처럼 다른 셸 이름이 찍히던 문제, Remote Control 세션이 프록시에 막혀 2분 가까이 '연결 중'에 머물던 문제, Cowork 클라우드 세션에서 WebFetch·WebSearch가 멈추던 문제(이제 300초 뒤 실패 처리)가 고쳐졌다. `claude mcp add`·`remove`·`/mcp`가 저장소 루트 아래 폴더에서 실행될 때 엉뚱한 이름을 보여 주던 문제와 백그라운드 세션 재시작 문제도 정리됐다.

AI 코딩 에이전트로 웹페이지를 만들면 비슷한 그라데이션, 비슷한 카드 배치, 비슷한 폰트가 반복된다. 이렇게 AI가 찍어낸 티가 나는 결과물을 흔히 'AI 슬롭(slop)'이라고 부른다. 이를 막아 주는 디자인 스킬 세 개가 깃허브에서 주목받고 있다. 스킬은 에이전트에게 특정 작업 방법을 알려 주는 지시문·자료 묶음이다.

첫째는 Nutlope의 hallmark다. 저장소 소개는 'Claude Code, Cursor, Codex용 안티 AI 슬롭 디자인 스킬'이다. README에 AI가 만든 것처럼 보이지 않게 하는 디자인 스킬이라고 설명돼 있다. 세 도구에서 모두 쓸 수 있다는 점이 장점이다.

둘째는 pbakaus의 impeccable이다. 'AI 하네스를 디자인에 더 능하게 만드는 디자인 언어'를 내세운다. 하네스는 모델을 감싸 도구와 작업 흐름을 붙여 주는 실행 환경이다. README에 AI 코딩 에이전트용 디자인 가이드 스킬이라고 나온다.

셋째는 alchaincyf의 Huashu Design 3.0이다. 에이전트에 한 문장만 입력하면 웹페이지, 앱 시안, 편집 가능한 PPTX, 애니메이션, 인포그래픽처럼 바로 넘길 수 있는 디자인을 만든다고 소개한다. README에 따르면 후보 여섯 개 중 세 방향을 고르는 방식과 예시가 붙은 84개 스타일 라이브러리를 갖췄다. 쓸수록 사용자의 취향을 기록하는 '외관 장부'와 디자인 점검 기능도 내세운다. HTML 기반이며 Claude Code, Codex, Cursor 등 어떤 에이전트에도 붙일 수 있다.

세 스킬은 모두 디자인 감각이 약한 개발자가 에이전트로 결과물을 만들 때 품질을 끌어올리는 데 쓸 수 있다. 실제 효과는 프로젝트마다 다르니, 같은 요청으로 스킬을 켰을 때와 껐을 때를 비교해 보고 고르는 것이 좋다.

AI 에이전트용 브라우저 ego lite와 Aside, Claude Code로 같은 작업 비교

Claude Code에 붙여 쓰는 AI용 브라우저 ego lite와 Aside를 같은 조건으로 비교한 영상이 나왔다. 속도는 Aside가 조금 빨랐다고 하나 개인 측정이며, 두 브라우저는 만든 목적과 보안 방식이 다르다.

로그인해야 보이는 웹 화면을 AI 에이전트가 다루게 하려면 일반 웹 요청이나 헤드리스 브라우저(화면 없이 돌아가는 브라우저)로는 막히는 경우가 많다. 그래서 AI가 사용자의 로그인된 브라우저를 쓰게 해 주는 'AI용 브라우저'가 나오고 있다. 한 유튜버가 그중 ego lite와 Aside를 같은 Claude Code, 같은 모델(Sonnet 5.5), 같은 지시문으로 비교했다.

ego lite는 싱가포르 Citro Labs가 만든 무료 브라우저다. 공식 저장소 README에 따르면 앱을 켜면 Claude Code·Codex 스킬 폴더에 ego-browser 스킬이 자동 설치되고, 에이전트마다 따로 Space(작업 공간)가 생긴다. 브라우저 안에는 AI가 없어 Claude Code 없이 열면 일반 브라우저다. macOS와 Windows만 지원하고 Linux는 로드맵에 있다.

Aside는 샌프란시스코 YC(2025 가을) 스타트업이 만들었다. 브라우저 안에 자체 AI 비서가 있어 브라우저만으로도 일을 시킬 수 있고, 이때 크레딧이 든다. 영상에 따르면 무료 계정은 월 500크레딧, Pro 월 20달러, Max 월 200달러이며 ChatGPT·Claude 구독을 연결할 수도 있다. Claude Code에는 MCP 서버(repl 도구)로 붙는다.

영상의 측정 결과는 위키 요약 평균 25초 대 34초, 해커뉴스 22초 대 30초, 유튜브 스튜디오 34초 대 39초로 세 작업 모두 Aside가 앞섰다. 유튜버는 1.1~1.4배 빨랐다고 정리했다. 다만 작업마다 2~3회씩 잰 개인 측정이라 확인된 수치는 아니다. 차이는 ego lite가 작업마다 550줄짜리 사용 안내서를 먼저 읽고 끝나면 작업 공간을 닫는 단계에서 생겼다고 한다.

보안 방식도 다르다. ego lite는 크롬 데이터를 통째로 가져와 편한 대신 에이전트도 그 계정으로 무엇이든 할 수 있다. Aside는 비밀번호 관리자(Vault)가 자동 입력만 하고 비밀번호를 에이전트에게 주지 않으며, 결제·게시·메시지 전송은 사용자 확인을 기다린다. reCAPTCHA 같은 사람 확인 단계에서는 둘 다 멈추고 사람이 넘겨받을 수 있다. 영상은 사이트 약관이 자동화 접속을 금지하는 경우가 있으니 실제로 쓰기 전에 약관부터 확인하라고 당부했다.

  • ego lite: 무료, Claude Code·Codex 스킬 폴더에 ego-browser 스킬 자동 설치, macOS·Windows만 지원
  • Aside: 자체 AI 비서 내장, MCP 서버로 연결, 무료 월 500크레딧
  • 세 작업 모두 Aside가 1.1~1.4배 빨랐다는 측정은 개인 실험으로 확인 안 됨
  • ego lite는 크롬 계정 통째 공유, Aside는 비밀번호를 에이전트에 주지 않고 결제·게시는 확인 대기
  • 자동화 접속 전 사이트 약관 확인 필요

핵심은 앱 안에 MCP 서버가 들어 있다는 점이다. 공식 데모 스킬인 openscreen-demo를 설치하면 Claude Code가 녹화, 자르기, 확대, 설명 문구, 자막과 번역, 내보내기 같은 앱 기능을 직접 다룬다. 영상 소개에 따르면 Claude Code는 먼저 장면 순서를 몇 줄로 보여 주고, 앱 창을 녹화한 뒤 클릭하는 곳마다 확대와 설명을 넣고 기다리는 구간은 자르거나 빨리 감는다. 내보낸 뒤에는 완성본 프레임을 다시 보며 문구가 가리거나 글자가 잘린 곳을 찾아 고친다.

X에는 사용자가 허락하기 전까지 올리지 않는다. 설치는 Claude Code에 `npx skills add getopenscreen/openscreen --skill openscreen-demo -y`로 스킬을 설치하라는 문장을 넣으면 된다. 스킬이 앱 설치(동의할 때만)와 MCP 연결까지 진행하고, 새 세션에서 'continue the OpenScreen demo'라고 입력하면 이어진다. macOS에서는 처음 실행할 때 화면 기록과 손쉬운 사용 권한을 허용해야 한다.

영상은 비슷한 유료 앱 Screen Studio가 맥 전용에 월 29달러이고, OpenScreen 원작 저장소가 깃허브 별 39,922개를 받았다고 소개했다. 이 두 수치는 이번에 확인되지 않았다. 원작 저장소(siddharthvaddem/openscreen)는 보관 처리됐고, 같은 이름과 라이선스로 getopenscreen/openscreen에서 개발이 이어지고 있다. 녹화와 편집, 자막 받아쓰기는 모두 로컬에서 돌아가며, OpenScreen은 앤트로픽과 관계없는 독립 프로젝트다.

GPT-6 Luna vs Haiku 5.5, Artlist MCP로 15초 영상 광고 만들기 대결

가벼운 모델 GPT-6 Luna(Codex)와 Haiku 5.5(Claude Code)에게 같은 제품 광고를 맡긴 비교 영상이 나왔다. 두 모델이 Artlist MCP로 이미지·영상을 만들고 15초 광고로 편집했다.

유튜브 채널 코드팩토리가 GPT-6 Luna와 Haiku 5.5 두 경량 모델에게 같은 제품 광고를 맡겨 비교했다. Luna는 Codex에서, Haiku는 Claude Code에서 작업했다. 이미지와 영상을 만들고 같은 문구와 음원으로 15초 광고를 편집하는 데까지 맡겼다. 영상은 Artlist 제휴 링크가 붙은 협찬성 콘텐츠다.

제품은 가상의 콜드브루 브랜드 '데이브레이크'다. 병 사진 한 장을 똑같이 주고 아침 커피 광고를 요청했다. 조건은 제품 모양과 색을 유지하고 마지막에 제품명과 문구를 읽을 수 있게 하는 것이었다. 평가 기준은 제품을 잘 보여 주는지, 요청을 잘 지키는지, 보기 좋은지 세 가지다.

두 모델은 광고를 기획하고 도구를 부르는 역할만 했다. 실제 이미지는 나노바나나 2.1, 영상은 시댄스로 양쪽 똑같이 만들었다. MCP로 Artlist를 연결해 에이전트가 대화 중에 생성을 직접 요청하게 했고, 최종 편집과 글자 배치는 하이퍼프레임즈에서 했다. 앞 단계에서 만든 이미지를 다운로드·업로드할 필요 없이 에이전트가 참조로 넘겨 영상을 만든다는 점이 MCP 연결의 장점으로 소개됐다.

이미지 단계에서 Luna는 제품을 크게 잡고 병 형태와 라벨을 유지했다. Haiku는 구도를 더 바꿔 문구를 올릴 여백과 아침빛을 넣었지만, 요청하지 않은 오렌지 조각이 생겼다. 유튜버는 제품 강조를 우선한다는 기준으로 이 단계에서 Luna에 더 높은 점수를 줬다. 제작과 검수에 감독 역할 에이전트를 함께 붙이는 방식도 추천했다. 한 사람의 주관적 비교라는 점은 감안해야 한다.

집에 둔 AI 작업용 PC를 밖에서 쓰는 법: Tailscale + SSH

24시간 켜 둔 집 컴퓨터에서 에이전트를 돌리고, 밖에서는 가벼운 노트북으로 Tailscale과 SSH를 통해 접속해 쓰는 방법을 소개한 영상이 나왔다.

유튜브확인할 사실 주장 없음
눌러서 본문 보기 ▾

에이전트 작업을 많이 하는 사람에게 유용한 원격 작업 구성 영상이 올라왔다. 집에 24시간 꺼지지 않는 PC를 두고, 밖에서는 가벼운 노트북으로 접속해 그 PC에서 에이전트를 돌리는 방식이다.

영상 속 유튜버는 맥 스튜디오 M4(64GB)를 집 서버로, 맥북 에어 M5(32GB)를 이동용으로 쓴다. 지하철에서 두 시간가량 에이전트로 일하는데 16인치 노트북은 무겁고 옆 사람과 부딪혀 가벼운 기기로 바꿨다고 했다. 고성능 노트북 한 대를 사는 것보다 집 데스크톱과 가벼운 노트북 조합이 낫다는 것이 그의 의견이다. 맥 스튜디오가 부담스러우면 맥 미니를 권했다.

방법은 세 단계다. 먼저 집 PC가 잠들지 않게 한다. 그는 무료 앱 캡썸니아를 추천했고 카페인 같은 다른 앱도 된다고 했다. 다음으로 Tailscale을 설치한다. Tailscale은 내 계정에 묶인 기기끼리만 통하는 사설 네트워크를 만들어 주는 앱이다. 기기마다 내 계정에서만 보이는 주소가 생기고, 내 계정으로 로그인하지 않으면 그 주소를 알아도 접속할 수 없다. 마지막으로 SSH(원격 컴퓨터에 명령을 보내는 프로그램)로 그 주소에 접속해 집 PC를 조작한다.

유튜버는 이 구성을 무전기 통신망에 비유했다. Tailscale이 통신망을 깔고, SSH가 그 통신망으로 명령을 주고받는다는 것이다. 터미널을 써야 하는 또 하나의 이유라고 덧붙였다. 장비 가격은 2026년 초보다 많이 올랐다고 했다.

  • 24시간 켜 둔 집 PC + 가벼운 노트북 조합으로 원격 에이전트 작업
  • 잠자기 방지 앱(캡썸니아 등) → Tailscale 사설 네트워크 → SSH 접속
  • Tailscale 주소는 내 계정으로 로그인한 기기만 접속 가능
  • 고가 노트북 한 대보다 데스크톱+경량 노트북이 낫다는 개인 의견

AI가 3D를 만드는 과정, 실행 기록으로 따라가 보기

자동차 사진 8장을 주고 AI에게 3D 모델을 만들게 한 뒤 실행 기록과 코드를 열어 과정을 되짚은 영상이 나왔다. 코드로 단면을 이어 붙이는 방식과 이미지→3D 모델의 차이를 설명한다.

AI가 3D 모델을 어떻게 만드는지 실행 기록을 열어 보여 주는 영상이 올라왔다. 유튜버는 자동차 사진 8장을 주고 로드스터 3D 모델을 만들게 했다. 첫 요청에 걸린 시간은 17분 7초였다. 사진 보기 14초, 도구 없이 생각만 9분 31초, 1,000줄 파일 한 번에 쓰기 약 3분, 결과 확인 약 4분이었다.

AI는 배를 만들듯 단면부터 시작했다. 앞에서 뒤까지 단면 10개에 바퀴 아치용 단면 25개를 더해 35개를 만들고, 이웃 단면의 점 4개를 이어 사각형을 만든 뒤 반으로 갈라 삼각형 두 개로 나눴다. 사각형 544개가 차체 삼각형 1,088개가 됐다. 꺾인 각이 26도를 넘는 곳만 모서리로 남겨 각진 느낌을 냈고, 타이어는 단면을 축 둘레로 64칸 돌려 만들었다.

영상은 TripoSR 같은 이미지→3D 모델이 반대 방향으로 작동한다고 설명한다. 사진을 조각 1,024개로 잘라 숫자로 바꾸고, 트랜스포머가 위·앞·옆 평면 세 장(트라이플레인)에 옮겨 적은 뒤, 공간의 점마다 물체 속인지 판단해 경계에 삼각형을 붙인다(마칭 큐브). 사진에 없는 뒷면은 학습한 3D 모델을 바탕으로 짐작해 채운다. 이 설명은 TripoSR 보고서(arXiv 2403.02151)를 출처로 들었지만, 이번 사실 확인에서 보고서를 직접 열어 보지 못해 세부 내용은 확인되지 않았다.

영상의 결론은 사진 같은 겉모습은 이미지→3D가 낫고, 부품 100개로 나눠 공중에서 분해하는 식의 구조적인 작업은 코드로 만드는 쪽이 쉽다는 것이다. 어떤 방식으로 시킬지 고를 때 참고할 만하다.

  • 사진 8장으로 로드스터 생성: 생각 9분 31초 후 1,000줄 파일 한 번에 작성
  • 단면 35개를 이어 차체 삼각형 1,088개, 26도 넘는 곳만 모서리 처리
  • 이미지→3D(TripoSR)는 트라이플레인·마칭 큐브 방식이라는 설명은 원문 미확인
  • 겉모습은 이미지→3D, 부품 분해 같은 구조 작업은 코드 방식이 유리

같은 일인데 비용 263배 차이…Claude Code 비용 줄이는 루프 설계 실험

한 유튜버가 같은 작업을 일곱 가지 방식으로 돌려 비용을 비교했다. Claude Code에 통째로 맡기기와 코드가 반복·검사를 맡고 Haiku만 부르는 루프의 비용 차이가 약 263배였다고 한다. 개인 실험이다.

유튜브⚠️ 일부 확인 안 됨
눌러서 본문 보기 ▾

Claude Code를 쓰면서 비용이나 사용량 한도가 빨리 닳는 경험을 한 사람이 많다. 한 유튜버가 같은 일을 일곱 가지 방식으로 시켜 비용을 비교한 실험을 공개했다. 과제는 유튜브 제목 후보 10개와 썸네일 문구 만들기이고, 모든 방식이 같은 형식 검사를 통과하도록 했다. 실험은 Claude Code 2.1.310으로 10월 26일에 했고, 방식마다 세 번씩 돌렸다. 비용은 Claude Code가 계산한 API 정가 기준이다.

영상이 밝힌 세 판 평균 비용은 이렇다. 통째로 맡기기 1.0071달러, CLAUDE.md 다이어트 0.9316달러, 판정만 코드로 0.8192달러, 도구만 끔 0.7161달러, 맨몸 Opus 0.0740달러, 맨몸 Sonnet 0.0397달러, 맨몸 Haiku 0.0038달러. 통째로 맡기기와 맨몸 Haiku의 차이가 약 263배라는 것이다. 다만 개인 실험 결과이고 공식 자료가 아니어서 이 수치는 확인되지 않았다. 영상 스스로도 모든 업무에서 같은 절감률이나 품질을 보장하지 않는다고 밝혔다.

영상이 설명하는 비용 구조는 세 가지 요소다. 요청마다 다시 읽는 입력량(맥락), 호출 횟수, 모델 단가다. Claude Code 기본 세션은 매 요청에 시스템 지시, 도구 설명, CLAUDE.md 같은 맥락을 다시 싣는다. '맨몸 호출'은 이런 맥락 없이 필요한 내용만 담아 모델을 부르는 방식이다. 판정만 코드로 바꿨을 때는 비용이 19%만 줄었는데, 맥락이 그대로 남아 있었기 때문이라고 영상은 분석했다.

영상이 권하는 루프 설계는 판정은 코드로, 일꾼 호출은 필요한 맥락만 담아, 재시도는 실패한 후보만 새 호출로, 초안은 작은 모델로 하는 것이다. CLAUDE.md를 줄이면 맥락은 작아지지만 오히려 턴이 늘어 절감 효과가 작았다는 관찰도 있다.

타입스크립트 강사 맷 포콕이 AI Engineer Paris 2026에서 에이전트 시대의 PR 병목을 다뤘다. 검사를 세 겹으로 두고, 코딩 규칙은 구현 에이전트가 아니라 리뷰 에이전트에게 주라는 것이 핵심이다.

Total TypeScript 강의로 유명하고 요즘은 AI Hero에서 에이전트 코딩을 가르치는 맷 포콕이 AI Engineer Paris 2026에서 「Fixing the PR Bottleneck」을 발표했다. 에이전트가 코드를 쏟아내면 PR(코드 변경 요청)은 늘어나는데 리뷰는 결국 사람이 해야 한다. 이 병목을 어떻게 풀지 다룬 강연을 한 유튜브 채널이 한국어로 정리했다.

포콕은 검사를 세 겹으로 본다. 맨 아래가 린트·타입 검사·테스트 같은 자동 검사, 그 위가 에이전트의 자동 리뷰, 맨 위가 사람 리뷰다. 앞의 두 겹을 단단하게 해서 사람 리뷰를 가볍게 만드는 것이 목표다. 나쁜 코드가 쌓이면 에이전트도 그 코드를 보고 나쁜 코드를 더 만들기 때문이다.

테스트가 통과했다고 믿으면 안 된다는 지적도 했다. 구현 값을 그대로 베껴 적은 테스트, 화면을 그려 보지 않고 소스 파일을 글자로 읽어 순서만 확인하는 테스트, 가짜 객체로 덮어 절대 실패할 수 없는 테스트가 대표적이다. 포콕은 AI가 일부러 나쁜 테스트를 쓴 게 아니라 시킨 대로 쓰다 코드 구조에 너무 붙어 버린 것이라고 봤다.

해법으로는 '깊은 모듈'을 제시했다. 복잡한 동작을 작은 인터페이스 하나 뒤에 숨긴 모듈을 말한다. 모듈이 깊으면 테스트도 그 인터페이스로만 하게 돼 속을 들여다보는 테스트가 줄어든다.

가장 실용적인 조언은 코딩 규칙을 구현 에이전트에게 넣지 말라는 것이다. 구현 에이전트는 코드를 찾고 고치고 디버깅하느라 컨텍스트가 이미 꽉 차 있다. 규칙은 별도 컨텍스트에서 도는 리뷰 에이전트(서브에이전트)에게 주고, AGENTS.md 같은 공용 파일이 아니라 코딩 규칙 파일에 따로 둔다. 리뷰 에이전트는 댓글을 다는 대신 커밋으로 직접 고친다. 포콕은 이를 레드·그린·리팩터를 컨텍스트 두 개로 나눈 것이라고 설명했다. 범용 외부 리뷰 서비스보다 팀이 직접 만든 리뷰 스킬을 권했다.

사람 리뷰는 되돌릴 수 있는 변경인지(one-way/two-way door)와 영향이 번지는 범위(blast radius)로 나눠 집중한다. 같은 리뷰 댓글을 두 번 쓰지 않도록 /retro로 반복 지적을 검사나 규칙으로 바꾸라는 조언으로 강연을 마무리했다. 영상은 포콕의 스킬 저장소가 깃허브 별 30만 개를 넘었다고 소개했지만, 이 수치는 확인되지 않았다.

  • 통과해도 믿으면 안 되는 테스트 세 유형: 구현 베끼기, 소스 글자 읽기, 실패 불가 가짜 객체

터미널 자체는 에이전트를 바라보는 창문일 뿐이고, 어떤 터미널을 써도 AI 성능은 달라지지 않는다고 설명했다. 웹 브라우저를 크롬으로 쓰든 사파리로 쓰든 네이버가 달라지지 않는 것과 같다는 비유다. 윈도우는 Wave, 맥은 Ghostty를 추천했지만 편한 것을 쓰면 된다고 했다.

ETH(Exponential Time Hypothesis)는 3-SAT 같은 어려운 문제를 지수 시간보다 근본적으로 빠르게 풀 수 없다는 가설이다. 비유하면 비밀번호를 찾으려면 수많은 조합을 하나씩 시도해야 하고, 이 노가다를 획기적으로 줄일 방법은 없다는 믿음이다. AI타임스 보도에 따르면 에이전트 '에코(Eko)'는 3D 세계를 텍스트로 관찰하고 bash 명령으로 이동, 점프, 물체 집기·놓기·던지기를 했다. 한 시간마다 섬과 대화 맥락을 초기화했지만 에이전트가 파일에 적은 기억은 남겼다. 보도는 MIT 연구진이 앤트로픽의 Claude Code와 Claude Opus 4.7로 에코를 만들었다고 전했지만, 초록에는 소속과 모델명이 없어 이 부분은 확인되지 않았다.

보도에 소개된 행동은 다양하다. 가장 높은 봉우리에 오르지 못한 에코는 바위를 옮기고 블록 두 개를 쌓아 발판을 만든 뒤 정상에 올랐다. 고리는 농구 골대, 과녁, 몸 장식으로 용도가 바뀌었다. 고리를 바다에 빠뜨린 에코는 잃어버린 고리를 기리는 하트 모양을 만들었다. 블록을 볼링 핀으로, 바위를 공으로 쓰기도 했다.

연구진이 주목한 것은 놀이가 기술 발견으로 이어졌다는 점이다. 13개 중 6개가 점프 도중 물체를 던지면 더 높이 던질 수 있다는 사실을 알아냈다. 가상 몸의 상승 속도가 물체에 더해지는 현상으로, 연구진도 시뮬레이터에서 가능한지 몰랐던 기술이라고 한다. 탐색하며 쌓은 경험은 이후 과제 수행에도 도움이 됐다.

커뮤니티 글은 모델마다 활동성이 달랐다고 전했다. Claude Opus 4.7은 놀이, 건축, 물리 실험을 활발히 했고, GPT-5.5는 작업 공간에 머물거나 쉬는 비중이 높았으며, Kimi K2.6은 활동 다양성이 제한적이었다는 것이다. 이 비교는 논문 원문으로 확인하지 못했다. 에이전트에게 파일로 기억을 남기게 하는 설계가 장기 작업에 효과적이라는 점은 Claude Code 사용자에게도 참고가 된다.

AI 도움으로 찾은 PHP 원격 코드 실행 취약점 'PHP2Shell'이 공개됐다. OpenAI는 점검 스킬을 내놨고, 같은 날 LiteLLM 1.107.0 악성 버전이 배포돼 AI 도구 설정까지 빼 간 사고도 있었다.

PHP로 돌아가는 서버를 로그인 없이 원격으로 장악할 수 있는 취약점 'PHP2Shell'이 공개됐다. 보안 회사 Wiz는 블로그에서 이 취약점을 PHP2Shell이라고 부르며, Gemini 4 Argon과 GPT-5.6 Sol 두 AI 모델을 써서 찾았다고 밝혔다. AI가 보안 연구의 실제 도구가 됐다는 점을 보여 주는 사례다.

PHP 보안 공지에 따르면 CVE-2026-109618은 인증 없이 원격으로 코드를 실행할 수 있는 취약점이고 CVSS(취약점 심각도 점수) 9.2를 받았다. 고친 버전은 8.5.12, 8.4.27, 8.3.36, 8.2.35다. 함께 다뤄지는 CVE-2026-109619까지 두 취약점이 10월 21일 패치됐다. 영상 자료에 따르면 8.1 이하는 정식 업데이트가 없고, mod_php 방식 서버가 가장 위험하다.

발견 경위도 공식 자료로 확인됐다. PHP 재단 블로그에 따르면 Calif 소속 연구자가 8월 11일 먼저 제보했고, OpenAI도 따로 같은 원인을 찾았다. 유튜브 정리 영상은 OpenAI가 이 일을 'Patch the Planet'이라는 이름의 공동 공개(coordinated disclosure) 활동으로 10월 21일 발표했다고 전했다. 워드프레스, 그누보드, 라이믹스 같은 국내외 PHP 기반 사이트 운영자가 영향을 받는다. 다만 영상 제목의 'PHP를 전 세계 웹사이트의 70%가 쓴다'는 수치는 공식 통계로 확인되지 않았다.

OpenAI는 점검용 스킬도 공개했다. php2shell-checker 저장소에 phpcheck-url과 phpcheck-server 두 스킬이 있다. URL 검사는 사이트 응답 머리글에 찍힌 PHP 버전만 읽고, 서버 검사는 서버 안에서 실제로 웹 요청을 처리하는 PHP를 확인한다. 결과는 OK, POTENTIALLY VULNERABLE(잠재적 취약), UNKNOWN(판단 불가) 세 가지로 나온다. 두 스킬 모두 공격 요청은 보내지 않는다.

주의할 점이 있다. 점검 영상은 패치를 깔았어도 실제 사이트는 옛 PHP로 돌아갈 수 있다고 강조한다. 웹 요청을 처리하는 PHP-FPM 워커(작업 프로세스)가 재시작되지 않으면 메모리에 옛 코드가 남아 있기 때문이다. 그래서 업데이트, 워커 재시작, 재검사를 모두 거쳐야 한다. UNKNOWN은 정보가 부족하다는 뜻이지 안전하다는 뜻이 아니고, OK도 표시된 버전이 기준을 넘는다는 뜻일 뿐 실제 반영을 보장하지 않는다. 영상은 10월 23일 PHP 팀이 CVE-2026-115560과 관련해 다음 정식 수정판 전까지 session.upload_progress.enabled = 0 설정을 권고했다는 추가 안내도 소개했다. 점검은 본인 소유이거나 허가받은 서버에서만 해야 한다.

해커들이 남의 서버에 들어가 대신 패치해 주고 나오는 일까지 있었다는 소개도 있었다. 선의라 해도 허가 없는 접속이라 법적 논란이 따를 수 있다. 영상 자료에 따르면 아마존은 공개 나흘 전 미끼 서버에서 공격 시도를 봤다고 했고, 미국 CISA는 발표 시점에 실제 공격을 관측하지 못했다고 했다.

같은 주에는 AI 개발자에게 더 직접적인 사고도 있었다. 여러 회사의 AI API를 한 가지 형식으로 묶어 주는 파이썬 라이브러리 LiteLLM의 1.107.0 버전이 10월 21일 악성 코드가 든 채로 PyPI와 Docker에 배포됐다. LiteLLM 공식 사고 공지에 배포 시간대와 조치 방법이 나와 있다. 정리 영상에 따르면 PyPI에는 약 1시간 44분, Docker에는 2시간 반가량 올라가 있었고, 설치만 돼 있어도 파이썬이 켜질 때마다 실행돼 SSH 키, 클라우드 키, 환경 변수, ~/.claude·~/.cursor 같은 AI 도구 설정 폴더를 빼 갔다.

LiteLLM은 Claude Code에 다른 모델을 붙일 때도 쓰인다. `pip show litellm`으로 버전을 확인하고, 1.107.0이 한 번이라도 깔렸다면 업데이트만으로 끝나지 않는다. 공지는 1.106.2로 고정하고 환경을 새로 만들고 키를 전부 교체하라고 권고했다. 영상은 침투 경로에 대해 회사가 '그렇게 보고 있다'는 단계라고 전하며, 로그에 남은 GitHub CLI 토큰이 탈취 경로로 지목됐다고 소개했다. Claude Code가 특정 상황에서 이 토큰을 응답 본문에 넣을 수 있다는 언급도 영상에 있으나, 이 부분은 이번 사실 확인에서 따로 검증되지 않았다. 프록시 뒤에서 Claude Code를 쓰며 응답 본문을 로그로 남기는 사람은 로그 관리 방식을 점검해 볼 만하다.
