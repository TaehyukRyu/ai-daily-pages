Claude Code v2.1.326 출시…에이전트 팀에서도 Code Mode, 도구 설정 실수는 시작할 때 경고

팀 기능과 Code Mode를 함께 쓰게 됐고 권한·설정 버그도 대거 고쳤다
v2.1.326 주요 변경
  • +에이전트 팀 + Code Mode 동시 사용
  • +--allowedTools·--tools 불완전 규칙 시작 경고
  • +/status에 기능 꺼짐 이유 표시
  • +Ctrl+O로 숨은 시작 알림 보기
  • ✓삭제·덮어쓰기 명령이 '읽기'로 보이던 문제 수정
  • ✓관리형 PreToolUse 훅 거부 기록 누락 수정
  • ✓저장 실패한 권한 규칙이 저장된 듯 보이던 문제 수정
출처: Claude Code
  • 에이전트 팀을 켠 상태에서도 Code Mode를 쓸 수 있다
  • --allowedTools 등에 불완전한 규칙이 있으면 시작할 때 경고한다
  • 파일을 지우는 Bash 명령이 '읽기'로 표시되던 문제를 고쳤다
자세히 보기

앤트로픽이 Claude Code v2.1.326을 내놨다. 공식 릴리스 노트 첫 항목은 에이전트 팀(여러 에이전트가 나눠 일하는 기능)을 켠 상태에서도 Code Mode를 켤 수 있게 했다는 내용이다. 이미 Code Mode를 켜 둔 사용자라면 팀 기능이 켜진 세션도 처음부터 Code Mode로 시작한다.

설정 실수를 미리 잡아 주는 장치도 늘었다. `--allowedTools`, `--disallowedTools`, `--tools`에 넣은 값 가운데 완전한 규칙처럼 보이지 않는 것이 있으면 시작할 때 경고를 띄운다. 허용·차단 목록을 잘못 적어 의도와 다르게 도구가 열리거나 막히는 일을 줄이려는 조치다. 세션 도중 관리자가 `managed-mcp.json`을 추가해 MCP 서버(외부 도구를 에이전트에 연결하는 서버)가 더 이상 불러와지지 않을 때 그 이유를 설명하는 메시지도 붙었다.

`/status`에는 사용 중인 제공자나 `DISABLE_TELEMETRY` 같은 환경 변수 때문에 기능이 꺼졌을 때 이를 알려 주는 줄이 생겼다. `/plugin`과 `claude plugin list`는 `plugin.json`의 `author`·`homepage` 같은 필드가 잘못돼 무시될 때 알려 준다. Ctrl+O로 숨겨진 시작 알림을 볼 수 있고, 요청이 실패한 뒤 빈 입력창에는 다음에 할 일을 알려 주는 힌트가 뜬다. 서브에이전트 화면에는 Esc로 멈출 수 있다는 안내가 붙었다.

권한과 관련된 버그 수정이 많다. `find -delete`, `cat a > b`, `sort -o`처럼 파일을 지우거나 덮어쓰는 Bash 명령이 대화 기록에 '검색'이나 '읽기'로 요약되던 문제를 고쳤다. 실제로는 파일을 바꾸는 명령이 읽기처럼 보이면 사용자가 위험을 놓칠 수 있었다. `/permissions`나 도구 승인 창에서 추가한 규칙이 설정 파일에 써지지 않았는데도 저장된 것처럼 보이던 문제도 고쳐, 이제는 어떤 파일인지 이름을 대며 경고한다.

관리형 설정 쪽도 손봤다. 관리형 설정에 넣은 PreToolUse 훅(도구 실행 직전에 도는 스크립트)이 도구 호출을 거부했을 때 OpenTelemetry `tool_decision` 이벤트와 `permission_denials` 기록이 남지 않던 문제가 고쳐졌다. 훅으로 사내 정책을 강제하는 팀은 거부 기록을 감사 로그에서 확인할 수 있게 됐다. 수천 단계로 중첩된 설정 값이 프로그램을 멈추게 하던 문제는 64단계를 넘는 값을 경고와 함께 버리는 방식으로 막았다.

백그라운드 세션이 충돌 뒤나 다른 폴더에서 다시 열릴 때 셸이 내보낸 LLM 게이트웨이 설정을 잃던 문제는, 이제 모델 요청을 보내기 전에 멈추도록 바뀌었다. 게이트웨이를 거쳐야 하는 회사 환경에서 엉뚱한 경로로 요청이 나가는 일을 막는 변경이다. 이 밖에 폴더 신뢰 확인 창에서 위 화살표와 Enter가 '예'로 처리되던 문제, 설치 마지막 Enter가 자동 모드 기본값 제안을 받아들이던 문제 등 실수로 승인되는 경로도 여럿 막았다.

PyTorch가 PyTorch로 만든 모델을 브라우저에서 GPU로 실행하는 'ExecuTorch WebGPU'를 공개했다. PyTorch 공식 블로그(2026년 11월 11일)에서 확인된다. 블로그는 Llama 3.2, Qwen3, Gemma 3 같은 작은 언어 모델과 Whisper(받아쓰기), MODNet(배경 지우기) 등을 검증된 모델로 소개했다.

이를 계기로 WebGPU를 풀어 설명한 영상이 올라왔다. WebGPU는 웹페이지가 내 컴퓨터의 그래픽카드(GPU)에 그림뿐 아니라 계산까지 시킬 수 있게 하는 웹 표준이다. 2011년에 나온 WebGL은 원래 그림을 그리려고 만든 통로라 계산을 시키기 어려웠다. WebGPU는 계산을 정식으로 지원하고, 맥에서는 Metal, 윈도우에서는 DirectX 12, 안드로이드·리눅스에서는 Vulkan 위에서 돈다.

영상 제작자는 맥 미니 M5 Pro, Chrome 157에서 3회 중앙값으로 직접 쟀다. 같은 크롬에서 WebGPU를 켰을 때와 껐을 때(꺼지면 CPU·WASM이 대신 계산)를 비교하면 30초 한국어 받아쓰기(Whisper base)는 1.5초 대 1.9초, 사진 한 장 배경 지우기(ISNet)는 0.2초 대 1.8초, 작은 언어 모델(Qwen3 0.6B)은 초당 166토큰 대 24토큰이었다.

같은 GPU에서 브라우저와 네이티브 앱을 비교하면 차이가 남았다. 언어 모델은 브라우저 WebGPU가 초당 166토큰, llama.cpp(Metal)가 343토큰, MLX가 438토큰이었다. 받아쓰기는 브라우저 1.3초, MLX 0.3초였다. 제작자는 실행 도구와 모델 형식 차이도 포함된 값이라고 밝혔다. 수치는 맥 한 대에서 잰 것이라 기기·브라우저에 따라 달라진다.

브라우저에서 AI를 돌리면 서비스 쪽은 계산을 사용자 GPU에 맡겨 서버 GPU 부담을 줄일 수 있다. 쓰는 쪽은 사이트가 따로 올리지 않는 한 사진·목소리가 서버를 거치지 않고, 모델을 받은 뒤엔 인터넷이 끊겨도 돌아간다. 단점도 있다. 처음 한 번 모델 파일을 통째로 내려받아야 해(Qwen3 0.6B 4비트 파일 약 919MB) 큰 모델은 아직 어렵다.

지원 범위는 Chrome·Edge가 윈도우·맥과 안드로이드 12 이상, Safari가 26 버전부터, Firefox가 윈도우와 애플 실리콘 맥이다. 크롬 주소창에 chrome://gpu를 넣어 'WebGPU: Hardware accelerated'가 보이면 된다. 써 볼 곳으로 chat.webllm.ai와 executorch.ai/playground가 소개됐다. Figma가 2025년 9월 렌더링 엔진을 WebGL에서 WebGPU로 옮기고 안 되는 기기에서는 WebGL로 돌아가게 한 사례도 Figma 블로그로 확인됐다. WebGPU 표준 자체는 아직 W3C 후보 권고안 초안 단계다.

영상의 결론은 네 수법이 모두 '시험지를 찍고, 밖으로 보내고, AI가 풀고, 답을 받는' 같은 구조라는 것이다. 수법마다 다른 것은 찍는 곳과 답을 받는 곳뿐이다. 스마트안경은 올해 중고교 내신에서 네 건이 적발됐다는 교육부 전수조사 보도가 있다. 반면 수신기를 어금니에 무는 방식은 시연 영상에만 나올 뿐 적발·보도 사례를 찾지 못했다고 제작자가 밝혔다.
