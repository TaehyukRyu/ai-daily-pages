어제 신문의 「앤트로픽 'Claude Meetings' 베타…화상 회의에 들어와 문서·화이트보드를 만든다」에 이어, 이 기능을 공식 발표문과 도움말로 풀이한 영상이 잇따라 나왔다. 앤트로픽은 11월 12일 Claude가 Google Meet 회의에 눈에 보이는 참석자로 들어오는 Claude Meetings를 베타로 공개했다. 공식 글로 확인된 사실이다.

새로 정리된 것은 쓰는 방법이다. 풀이 영상에 따르면 Claude의 Meetings 화면에서 구글 캘린더를 연결하고 회의를 골라 'Add Claude'를 누르면 된다. 모든 회의 또는 1:1을 뺀 회의에 자동으로 참석하게 할 수도 있다. Claude는 참가자 칸으로 보이고, 칸에 지금 하는 일이 표시된다.

회의 중에는 "Claude" 하고 말로 부르거나 Meet 채팅에 입력해 묻는다. 기본 답은 채팅창에 글로 오며, 통화 참가자 모두에게 보인다. 문서·화이트보드·슬라이드 같은 결과물(아티팩트)을 회의 중에 만들고 초대된 팀원이 같이 고칠 수 있다. 슬랙 같은 연결 도구도 쓸 수 있는데, 각자의 도구는 그 사람의 허락을 처음 한 번 받고 이후 유지된다고 영상은 설명했다.

회의가 끝나면 요약·결정 사항·할 일·정하지 못한 질문이 담긴 회의록과 대화 기록, 만든 결과물이 claude.ai 회의 페이지에 모이고, 초대된 사내 사람에게 요약 메일이 간다. Gong·Granola·Fireflies.ai·Otter 등 다른 회의록 서비스로 기록을 보내는 기능은 '곧' 나온다고만 돼 있어 아직 쓸 수 없다.

제약도 분명하다. 지금은 Google Meet만, Team·Enterprise 요금제만 쓸 수 있고 차례로 열리는 중이다. 데이터를 남기지 않는 ZDR, HIPAA-ready, 고객 관리 키(CMEK)를 쓰는 조직은 베타 동안 제외된다. 이 내용은 공식 글로 확인됐다. 영상에 따르면 외부 손님이 있는 회의는 Enterprise에선 기본적으로 막히고 Team에선 허용되며, 허용된 회의에서도 Claude는 채팅으로 답하지 않고 듣고 적기만 한다. 음성 파일은 저장하지 않지만 대화 기록과 요약은 저장되므로, 넣기 전에 참석자 모두의 동의를 받으라는 것이 공식 안내다.

요금은 베타 동안 노트·대화 기록·연결 도구를 안 쓰는 답변이 요금제에 포함되고, 회의에서 만든 문서·화이트보드는 2027년 2월 10일까지 무료다. 이것도 공식 글과 일치한다. 연결 도구를 쓰면 그 사람의 사용량에서 빠진다.

앤트로픽이 Claude Code v2.1.325를 내놨다. 공식 릴리스 노트의 첫 줄은 보안 수정이다. zstd로 압축된 응답을 풀어 읽는(디코딩) 과정에 있던 보안 문제를 고쳤다고 밝혔다. zstd는 데이터를 작게 줄여 주고받는 압축 방식이다. 노트는 문제의 구체적인 내용은 적지 않았지만, 보안 항목인 만큼 바로 업데이트하는 편이 낫다.

사용자가 직접 체감할 변화도 있다. 조직 정책이 요청을 막으면 지금까지는 오류만 떴는데, 이제 그 아래에 이어가는 방법이 한 줄 붙는다. `/rewind`로 되돌아가 메시지를 고치거나 `/clear`로 대화를 비우라는 안내다. 회사 계정에서 정책 차단을 자주 겪던 사용자에게는 막힌 자리에서 무엇을 해야 하는지 알려 주는 변화다.

VS Code처럼 편집기 안에 붙은 터미널에서는 Claude가 Jupyter 노트북을 읽거나 고친 뒤 '노트북 셀을 다시 실행하라'는 팁이 스피너(작업 중 표시)에 한 번 뜬다. 샌드박스 안에서 `git checkout`, `git stash`, 자동 stash가 `.claude` 폴더 같은 보호된 파일을 바꾸지 못하면 Claude에게 그 사실을 알려 주는 메모도 추가됐다.

서브에이전트 관련 수정이 눈에 띈다. 모델 설정이 `opusplan`이나 `haiku`일 때 자기 모델을 따로 지정한 서브에이전트가 계획 모드용 모델로 바뀌어 버리던 문제를 고쳤다. 다른 모델로 도는 서브에이전트가 파일 읽기와 MCP 결과 크기를 메인 세션 모델 기준으로 재던 문제도 고쳤다. 서브에이전트에 싼 모델을 붙여 비용을 나누던 사용자라면 의도대로 동작하는지 다시 볼 만하다.

세션 안정성도 손봤다. 여러 서드파티 게이트웨이와 Foundry에서 대화를 압축(compact)하지 못하고 매 턴 컨텍스트 길이 오류로 멈추던 문제, 깔끔하게 종료되지 않은 뒤 세션을 다시 열면 최근 턴이 빠지던 문제가 수정됐다. 작업 폴더가 지워진 뒤 셸 명령이 처음 실행한 폴더에서 돌던 문제는 이제 메시지와 함께 실패하고 다시 내릴 수 있게 바뀌었다.

계획 저장도 바뀌었다. `plansDirectory` 폴더에 승인된 계획을 저장하지 못하면 계획이 사라지던 문제를 고쳐, 기본 계획 폴더에 저장하고 어디에 왜 저장했는지 경고로 알려 준다. 저장된 `sonnet[1m]` 설정이 새로 설치할 때 API가 받지 않는 모델 ID로 바뀌던 문제도 고쳤다.

그 밖에 `/security-review`와 스킬 속 git 명령이 bare 저장소의 워크트리, `--separate-git-dir` 체크아웃, 안드로이드 `repo` 체크아웃에서 오류로 멈추던 문제, `/stats`의 활동 일수가 하루 많게 나오던 문제, `/insights`가 분석할 세션이 없는데도 보고서가 준비됐다고 하던 문제와 HTML 보고서에 값 두 개를 이스케이프 없이 쓰던 문제, `claude purge`가 터미널이 없을 때 조용히 멈추던 문제 등이 고쳐졌다. 로그인·`/fast`·`/model` 안내 문구가 실제 상태와 다르게 나오던 문제도 여럿 정리됐다.

AI 비서 앱 피클(Pickle)을 설치부터 전화 걸기, 오늘의집 장바구니 담기, 고속버스 조회, 카카오톡 연동까지 직접 써 본 후기 영상이 나왔다. 영상은 피클이 앱스토어 생산성 1위에 올랐고 무료로 쓸 수 있다고 소개했지만, 순위와 요금·기능을 확인할 공식 자료는 찾지 못했다.

영상에서 제작자는 피클에게 가족 단톡방 메시지를 보내게 하고, 전화를 대신 걸게 했다. 집들이 선물 세 개를 골라 장바구니에 담게 했고, 아침 브리핑 같은 예약 작업도 걸어 봤다. 고속버스 시간표를 조회해 캘린더에 연결하는 장면도 있다.

카카오톡 연결은 기기 인증 과정에서 PC 카카오톡이 로그아웃되는 일이 있었다고 한다. 제작자는 카카오 운영정책의 '허용하지 않는 방법에 의한 이용' 조항을 확인했지만 연동이 정책에 맞는지는 확인하지 못해 연동을 끊을지 판단해야 했다고 밝혔다.

장점으로는 쉬운 연결을, 단점으로는 느린 작업 속도와 적은 사용 한도를 꼽았다. 피클 이용자끼리 일정을 나누는 기능도 다뤘는데, 이때 어떤 정보가 상대에게 공개되는지 살펴야 한다고 짚었다. AI 비서에게 전화와 메신저를 맡기는 일은 편리하지만, 서비스 약관과 개인정보 범위를 먼저 확인할 필요가 있다.

컴퓨터 세 대에 흩어진 코딩 에이전트와 세션을 한 화면에서 다루는 도구 세 가지를 비교한 영상이 나왔다. 오르카(Orca), 파세오(Paseo), 허더(herdr)다. 제작자는 기존 세션 검색, 화면 분할, 모바일 연결, 메모리 사용량을 직접 써 보며 견줬다.

오르카는 기존 세션을 불러오고 검색하는 기능이 강점으로 소개됐다. 파세오는 모바일 연결과 재시작 뒤 세션 복원을 지원하는데, 복원은 설정을 켜야 한다. 기존 세션을 대량으로 가져오기 어렵다는 평가는 제작자 개인 경험이다. 허더는 메모리를 적게 쓰고 화면을 레인으로 나눠 쓴다.

허더 모바일은 SSH로 herdr-core에 연결하며 허더 TUI(터미널 화면) 세션은 지원하지 않는다. 이 점은 허더 공식 안내로 확인됐다. herdr-core는 데스크톱 앱에 들어 있고 따로 설치할 수도 있다.

영상 속 메모리 수치는 맥 액티비티 모니터 기준으로 오르카 약 540MB, 파세오 약 875MB, 허더 TUI 약 70MB였다. 제작자는 앱·데몬·세션 상태가 달라 같은 조건의 성능 비교가 아니라고 밝혔다.

그 밖에 다른 컴퓨터로 작업을 넘기는 '핸드오프' 실습도 다뤘다. 이 핸드오프는 인수인계서를 전달할 뿐 로컬 파일이나 커밋하지 않은 변경은 옮기지 않으며, Claude Code의 얼리 액세스 기능 훅을 쓰므로 버전 호환성을 확인하라고 안내했다. 에이전트 실행 과정을 추적하는 Phoenix와 학습 지표를 보는 Trackio도 짧게 소개됐다.

Claude Code와 Codex를 만든 앤트로픽과 OpenAI가 공식 문서에 적어 둔 사용 습관을 정리한 영상 두 편이 공유됐다. 대화가 길어질수록 에이전트가 엉뚱해지는 문제를 줄이는 방법이 중심이다. 핵심 권고 가운데 Claude Code 쪽 내용은 공식 문서로 확인됐다.

첫째, 작업이 바뀌면 새 대화로 시작한다. Claude Code는 `/clear`, Codex는 `/new`다. Claude Code Best practices 문서에는 '관련 없는 작업 사이에 /clear'라는 권고가 실제로 있다. 끝난 작업 기록까지 매번 다시 읽지 않게 돼 비용도 줄어든다. 영상은 하나만 고르라면 이 습관이라고 했다. 다만 같은 문제를 계속 푸는 중이면 그 대화에 머무는 편이 낫다.

둘째, 두 번 고쳐 줬는데 또 틀리면 세 번째로 고치지 말고 새로 시작한다. 문서에는 '두 번 수정에 실패하면 /clear 후 더 나은 프롬프트를 쓰라'는 문구가 있다. 셋째, 시킬 때 끝난 기준까지 말한다. '고친 다음 테스트를 실행해 통과하는지 확인해 줘'처럼 확인 방법을 같이 주면 에이전트가 고치고 돌려 보기를 혼자 반복한다. Codex 문서가 쓰는 목표·맥락·조건·완료 기준(Goal·Context·Constraints·Done when) 틀도 소개됐다.

넷째, 같은 말을 반복하게 되면 규칙 파일(CLAUDE.md나 AGENTS.md)에 적되 짧게 유지한다. Claude Code Memory 문서는 CLAUDE.md 파일 하나를 200줄 아래로 두라고 권한다. 테스트 명령, 코드만 봐서는 오해하기 쉬운 부분, 두 번 고쳐 준 실수를 적는 식이다. 규칙 파일은 참고 사항이라 반드시 지켜야 할 규칙은 훅이나 자동 검사로 강제하라는 조언도 붙었다.

다섯째, 큰 작업은 계획부터 받는다. 영상은 두 도구 모두 Shift+Tab으로 계획 모드를 켜고 Codex는 `/plan`도 된다고 했지만, 이 부분은 확인되지 않았다. Claude Code 문서에서는 Shift+Tab이 권한 모드를 순서대로 바꾼다는 내용만 확인됐다.

긴 영상은 캐시도 다룬다. Claude Code 프롬프트 캐시 수명은 구독 한도 안에서 약 1시간, API 키·크레딧은 5분, 서브에이전트는 기본 5분이라는 내용은 문서로 확인됐다. 대화 도중 모델을 바꾸면 캐시가 모델마다 따로라 처음부터 다시 읽게 된다는 점, 에이전트를 여러 개 띄울 땐 워크트리로 작업 폴더를 나누라는 점도 다뤘다. 대문자 IMPORTANT 강조나 'think hard' 같은 주문은 이제 안 해도 된다는 표도 소개됐다. 영상은 11월 13일 기준 문서이며 문서가 자주 바뀐다고 밝혔다.

앤트로픽이 기업공개(IPO)를 위해 미국 증권거래위원회(SEC)에 Form S-1 등록 서류를 제출했다고 공식 발표했다. S-1은 미국에서 주식을 처음 공개적으로 팔기 전에 회사 사업과 재무를 알리는 서류다. 발표문 게시일은 자료마다 11월 10일과 10월 26일로 다르게 표시돼 있다.

발표에 따르면 앤트로픽은 Class A 보통주를 나스닥 글로벌 셀렉트 마켓에 티커 'ANT'로 상장할 계획이다. 공모할 주식 수와 가격 범위는 아직 정하지 않았다. 등록 서류는 제출됐지만 아직 효력이 생기지 않아 지금은 주식을 팔거나 매수 주문을 받을 수 없다고 밝혔다. 예비 투자설명서는 골드만삭스와 모건스탠리를 통해 받을 수 있다.

커뮤니티에서는 상장을 앞두고 다리오 아모데이 앤트로픽 CEO와 제이미 다이먼 J.P. Morgan CEO가 뉴욕 J.P. Morgan 본사에서 대담했고, 이 장면이 앤트로픽 공식 유튜브로 생중계됐다는 글이 공유됐다. 그러나 이번 생중계를 다룬 공식 자료는 찾지 못해 확인되지 않았다. 검색에서는 2026년 5월에 열린 두 사람의 별도 대담 기록만 나왔다.

상장이 이뤄지면 앤트로픽은 정기적으로 재무 정보를 공개해야 한다. Claude 요금이나 사용 한도 같은 정책이 어떤 사업 판단에서 나오는지 지금보다 더 드러날 수 있다는 점에서 개발자들에게도 지켜볼 만한 일이다.
