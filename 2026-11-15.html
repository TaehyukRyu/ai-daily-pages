LG AI연구원이 11월 9일부터 대형 언어 모델 K-EXAONE 2.5를 API로 무료로 열었다. EXAONE API 문서의 변경 기록 11월 9일 항목에 API 공개와 '현재 무료로 제공'이라는 문구가 있다. 종료일은 정해지지 않았다.

모델 문서에 따르면 K-EXAONE 2.5는 전체 750B(7,500억 개) 매개변수 가운데 한 번에 31B만 쓰는 구조다. 글자만 입력할 수 있고 이미지는 넣을 수 없다. 지식 기준 시점은 2026년 1월이다. 엔드포인트 문서에는 최대 입력 524,288토큰, 모델 이름 k-exaone_v2.5, 생각 깊이(reasoning_effort) 옵션 low·high·max(기본 max)가 나온다. LG가 공개한 SWE-Bench Pro(실제 소프트웨어 문제 해결 벤치마크) 점수는 59.21이다. LG 자체 측정이며, 영상이 함께 소개한 비교 수치는 DeepSeek-V4.1-Flash 58.41, GLM-5.3 64.03이다.

쓰는 법은 간단하다. OpenAI 호환 API라서 openai 파이썬 라이브러리에서 base_url을 EXAONE 주소로, 모델을 k-exaone_v2.5로 바꾸면 된다. 생각 과정(reasoning_content)과 답(content)이 따로 오고, 생각은 끌 수 없다. 영상에 따르면 도구 호출도 되고 병렬 호출도 확인됐다. 키는 EXAONE ID에 가입(만 19세 이상)한 뒤 API 문서 사이트에서 발급한다.

무료 조건은 꼼꼼히 봐야 한다. 이용약관(11월 9일 시행)에 따르면 비상업적 용도만 허용돼 영리 목적이나 내 서비스에 붙여 남이 부르게 하는 것은 안 된다. API 키는 발급 30일 뒤 자동으로 꺼지고, 입력과 출력이 모델 학습에 쓰일 수 있다. 영상은 기본 하루 100회, 초당 1회·분당 60회 한도라고 소개했지만, Rate Limits 문서에 공식 수치가 없어 확인되지 않았다.

영상 제작자는 11월 14일 같은 문제 19개(수학 5·한국어 7·코딩 6·긴 문서 1)를 OpenAI GPT-6-Luna와 두 번씩 풀게 해 비교했다. 제작자가 직접 잰 값으로 공식 자료는 없다. 제작자 집계로는 100점 환산 EXAONE 91점, Luna 95점이었다. 어려운 수학 한 문제는 EXAONE이 더 자주 맞혔고, 한글 금액 쓰기·맞춤법·숫자 읽기 코드는 Luna가 앞섰다고 한다.

속도는 큰 약점으로 지적됐다. 제작자 측정에서 EXAONE은 출력 토큰이 Luna보다 약 40배 많았고, 맞춤법 한 문장 고치기에 평균 수백 초가 걸렸다고 한다. 공개 직후라 서버가 붐벼 동시 요청 거절(429 오류)도 잦았다고 한다. 표본이 작고 서버 상태에 따라 달라질 수 있는 측정이라 참고로만 보는 것이 맞다.

정리하면, 한국어 대형 모델을 개인 실험이나 공부용으로 공짜로 써 보기에는 좋은 기회다. 다만 상업 서비스에 붙일 수 없고 키가 30일마다 꺼지며 입력이 학습에 쓰일 수 있다는 점은 미리 알아 둬야 한다.

크롬 개발자 도구 팀의 저장소 chrome-devtools-mcp가 깃허브 트렌딩에 올랐다. 저장소 소개는 'Chrome DevTools for coding agents', 즉 코딩 에이전트를 위한 크롬 개발자 도구다.

이 도구는 MCP 서버다. MCP(Model Context Protocol)는 AI 에이전트가 바깥 도구를 부를 수 있게 하는 표준 연결 방식이다. README에 따르면 이 서버를 붙이면 코딩 에이전트가 실제 크롬 브라우저를 제어하고 검사할 수 있다.

웹 개발에서 이 차이는 크다. 지금까지 에이전트는 코드를 고쳐 놓고 화면이 실제로 어떻게 나오는지는 사람에게 확인을 맡기는 경우가 많았다. 브라우저를 직접 다룰 수 있으면 에이전트가 페이지를 열고, 콘솔 오류나 네트워크 요청 같은 개발자 도구 정보를 보고, 고친 뒤 다시 확인하는 일을 스스로 할 수 있다.

Claude Code처럼 MCP를 지원하는 도구라면 설정에 서버를 추가해 쓸 수 있다. 오늘 소개한 SSE 풀이 영상(s8)도 크롬 개발자 도구로 찍은 화면을 썼듯, 개발자 도구는 웹 동작을 확인하는 기본 도구다. 이번 저장소는 그 도구를 에이전트 손에 쥐여 준다는 점에서 눈여겨볼 만하다.

Claude Code에 새 대화를 열 때마다 같은 설명을 다시 하고, 고쳤던 실수를 다음 작업에서 또 만나는 일은 흔하다. Compound Engineering은 이 문제를 겨냥한 Claude Code 플러그인이다. 일이 하나 끝날 때마다 배운 것을 문서로 남기고, 다음 작업이 그 문서를 읽게 한다. 이름의 'compound(복리)'처럼 배운 것이 쌓일수록 다음 작업이 쉬워진다는 생각이다.

저장소 README에 따르면 /ce-compound 명령으로 배운 것을 docs/solutions/ 폴더에 남기는 흐름이 핵심이다. 플러그인은 미디어 회사 Every의 공식 플러그인이고, README에는 Kieran Klaassen과 Trevin Chow가 관리한다고 적혀 있다. Klaassen은 Every에서 이메일 앱 Cora를 맡은 개발자로, Every의 개발 방식을 묶어 공개했다. 영상은 'Every가 Cora를 비롯한 제품 다섯 개를 주로 개발자 한 명씩 맡아 운영한다'고 소개했지만, 이 내용은 공식 페이지에서 확인되지 않았다.

작업은 정해진 순서로 흘러간다. 코드를 쓰기 전에 질문 하나와 추천안을 먼저 내놓고, 그다음 계획·구현·검사 순서로 진행한다. 검사 단계에서는 만든 기능을 실제로 돌려 보면서 부탁하지 않은 기존 버그까지 짚는다. 검사에서 잡은 실수는 '오답 노트'처럼 남겨 두고, 같은 실수를 막는 테스트로 만들기도 한다.

소개 영상을 만든 채널은 11월 14일 연습용 할 일 관리 CLI(명령줄 프로그램)에 같은 부탁을 플러그인을 켠 Claude Code와 끈 Claude Code에 두 번씩 맡겼다. 숨겨 둔 버그는 플러그인 쪽이 두 번 모두 찾았다고 한다. 다만 한 채널이 두 번씩 돌려 본 결과라 일반적인 성능 차이로 보기는 어렵다. 영상 기준 버전은 플러그인 3.38.1, Claude Code 2.1.323이다.

혼자 여러 기능을 맡아 개발하는 사람이라면 써 볼 만하다. 규칙 파일(CLAUDE.md)에 모든 것을 몰아 적는 대신, 작업마다 생긴 교훈을 별도 문서로 쌓는 방식이라는 점이 다르다. 설치는 Claude Code의 플러그인 명령으로 한다.

ChatGPT나 Claude의 답이 한 글자씩 흘러나오는 것은 서버가 답을 다 만들 때까지 기다리지 않고 만드는 대로 조각조각 보내기 때문이다. 이 원리를 식당에 빗대 설명한 짧은 영상이 나왔다.

영상은 서버가 먼저 내용을 보내는 방법을 세 가지로 나눈다. 폴링은 일정 간격으로 '새 거 있어요?' 하고 계속 묻는 방식이다. 대부분 헛걸음이지만 단순해서 가끔 확인하면 되는 일에 지금도 쓰인다. 서버가 새 내용이 생길 때까지 답을 미뤘다 보내는 롱 폴링도 있다.

SSE(Server-Sent Events)는 연결을 한 번 열어 두면 서버가 새 내용이 생길 때마다 계속 흘려보내는 방식이다. 방향은 서버에서 브라우저로 하나뿐이다. 질문은 처음에 일반 요청으로 보내고 답만 SSE로 받는 구조다. Anthropic 공식 문서에도 stream:true를 켜면 답을 server-sent events로 보낸다고 적혀 있다. 영상은 OpenAI·Google도 마찬가지라고 설명했다.

웹소켓은 처음에 연결 방식을 바꾸자고 요청한 뒤, 양쪽이 아무 때나 주고받는 방식이다. 영상에 따르면 목소리로 대화하는 API들이 이 방식을 쓴다. 고르는 기준은 간단하다. 가끔 확인하면 되면 폴링, 서버가 한쪽으로 계속 보내면 SSE, 양쪽이 수시로 주고받으면 웹소켓이다.

바이브코딩을 하다 AI가 '실시간 기능은 웹소켓으로 만들까요?'라고 물으면, 서버만 보내는 일인지부터 따져 보라는 것이 영상의 조언이다. 그렇다면 SSE가 더 간단할 수 있다. 다만 SSE를 HTTP/1.1로 쓰면 브라우저가 한 사이트에 연결을 6개까지만 열어 탭이 많으면 막힐 수 있고, HTTP/2로 서비스하면 이 제한이 크게 풀린다고 한다.

Zajno Motion(Motion.ed)은 디지털 스튜디오 Zajno가 만든 사이트로, 2023년 5월 22일 웹디자인 시상식 Awwwards의 '오늘의 사이트'로 뽑혔다. 사이트에는 easing(속도 변화), offset and delay(시차), fade(서서히 나타나기), morph(형태 바꾸기), masking(가려서 드러내기), parallax(겹겹이 다른 속도로 움직이기), zoom 같은 기법이 예시 애니메이션과 함께 나온다. 영상은 scale까지 8가지라고 했지만 scale은 따로 된 섹션이 없었고, 무료라는 표시도 사이트에 따로 없다.

영상 제작자는 11월 13일 Claude Code에 가상의 커피 로스터리 12초 인트로를 부탁하면서 기법 이름 8개를 순서대로 적고 morph, masking, zoom 세 장면에만 한 줄 설명을 붙였다. 이름을 적은 요청과 적지 않은 요청을 두 번씩 돌렸더니 결과를 모르는 판정자가 이름을 적은 쪽을 더 높게 골랐다고 한다. 다만 제작자 혼자 한 실험이어서 '기법 이름을 적으면 결과가 나아진다'는 주장은 확인되지 않았다.

그래도 용어를 알면 요청을 구체적으로 쓸 수 있다는 점은 분명하다. 사이트에서 예시를 보고 마음에 드는 움직임의 이름을 골라 요청문에 적어 보는 정도라면 부담 없이 시도할 수 있다.

얀 르쿤이 저자로 참여한 JEPA 논문이 커뮤니티에서 소개됐다. 제목은 'Proving and Improving the Platonic Representation Hypothesis with JEPAs'이고, 저자는 Randall Balestriero와 Yann LeCun, 소속에 AMI Labs가 표시돼 있다(저자별 소속은 따로 나오지 않는다).

JEPA(결합 임베딩 예측 구조)는 르쿤이 오래 밀어 온 학습 방식으로, 입력 자체를 맞히기보다 입력의 의미를 담은 특징(표현)을 예측하게 하는 구조다. 제목의 '플라톤 표현 가설'은 서로 다른 데이터로 따로 학습한 모델들이 결국 비슷한 세계 표현에 도달한다는 가설이다.

논문 정리에 따르면, 같은 짝 관계(무엇과 무엇이 같은 대상인지)로 학습한 JEPA들은 이상화된 조건에서 '회전 하나만큼만 다른 같은 표현'을 복원한다. 쉽게 말해 이미지만 보고 배운 인코더와 텍스트만 보고 배운 인코더가 만든 특징을 회전 변환 하나로 이어 맞출 수 있다는 것이다. 커뮤니티 글은 LeJEPA의 성능을 높이는 학습 방법도 함께 제시됐다고 소개했다.

다만 이 결과는 이상화된 가정 아래에서만 성립한다고 논문이 밝힌다. 커뮤니티 글은 '모든 정보를 하나의 기하학 모형에 담을 수 있다', '월드모델의 실마리', '로봇 인지에 큰 진전' 같은 해석을 덧붙였지만, 이는 글쓴이의 기대이고 논문이 실제 시스템에서 보여 준 결과는 아니다. 당장 쓸 수 있는 도구가 나온 것이 아니라 연구 방향을 보여 준 논문으로 보는 것이 맞다.
