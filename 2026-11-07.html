Claude Code v2.1.319, 게이트웨이 뒤 auto mode 바꾸고 MCP 작업은 백그라운드로

권한 프롬프트 대신 거부하는 설정과 지연 최적화 명령도 새로 들어왔다
v2.1.319 주요 변경
  • ✓게이트웨이 뒤 auto mode: 확인 못 한 호출은 묻거나 거부
  • +터미널에서 MCP 작업 백그라운드 처리
  • +permissions.denyInsteadOfPrompting 설정
  • +/claude-api latency-optimize 명령
  • +CLAUDE_CODE_DISABLE_FEATURE_FLAGS 환경 변수
  • +/tasks에 끝난 서브에이전트 목록
  • +ant auth login 과금 조직 경고
  • ✓HEAD 파일 있을 때 /diff 오류 등 버그 수정
출처: Claude Code
  • 게이트웨이·텔레메트리 꺼진 환경의 auto mode는 확인 못 한 호출을 묻거나 거부한다
  • MCP 서버의 긴 작업은 바로 백그라운드로 가고 끝나면 결과를 알린다
  • 프롬프트 대신 거부하는 permissions.denyInsteadOfPrompting이 새로 생겼다
자세히 보기

앤트로픽이 Claude Code v2.1.319를 내놨다. 공식 릴리스 노트를 보면 가장 큰 변화는 auto mode다. auto mode는 도구 호출을 사람이 일일이 승인하지 않아도 되도록 Claude Code가 안전 여부를 따져 알아서 허용하거나 막는 모드다. 이번 버전부터는 텔레메트리(사용 정보 전송)나 기능 플래그를 꺼 둔 환경, 그리고 LLM 게이트웨이(회사가 모델 호출을 한곳으로 모아 중계하는 서버) 뒤에서는 서버가 확인하지 못한 호출을 사용자에게 묻거나 거부한다. 예전처럼 내장 분류기로 넘어가 판단하는 길은 없어졌다. 내장 분류기를 계속 쓰려면 `CLAUDE_CODE_AUTO_MODE_SERVER=0`을 설정하면 된다. Bedrock, Vertex, Foundry 환경은 바뀌지 않는다.

반대로 게이트웨이 뒤에서 `CLAUDE_CODE_AUTO_MODE_SERVER=1`을 켜면 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS`가 설정돼 있어도 서버 쪽 검사가 켜진다. 관리형 설정(managed settings)으로 후자를 강제하는 조직이라면 `1`도 함께 넣어야 한다. 사내 게이트웨이를 쓰는 팀은 업데이트 뒤 auto mode에서 갑자기 질문이나 거부가 늘 수 있으니 설정을 먼저 확인하는 편이 좋다.

두 번째 변화는 MCP 작업(task) 지원이다. MCP 서버가 도구 호출을 시간이 걸리는 '작업'으로 돌리면 Claude Code가 이를 곧바로 백그라운드로 보내고, 끝나면 결과를 Claude에게 알려 준다. 긴 빌드나 데이터 처리를 맡겨 놓고 대화를 이어 갈 수 있다는 뜻이다. 기다리는 쪽이 낫다면 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` 환경 변수로 예전처럼 도구 호출 안에서 기다리게 할 수 있다.

`permissions.denyInsteadOfPrompting` 설정도 새로 생겼다. 권한 프롬프트를 띄우고 기다려야 할 도구 호출을 그냥 거부하고 턴을 이어 간다. 터미널 세션, 서브에이전트, 팀메이트(teammate)에서 모두 동작한다. 사람이 붙어 있지 않은 자동 실행에서 프롬프트 하나 때문에 작업이 멈추는 일을 막을 수 있다.

`/claude-api latency-optimize` 명령은 Claude API를 쓰는 코드에서 사용자가 기다리게 되는 지점을 찾아, 더 빠른 설정을 평가(eval)에 대고 시험해 본다. 기능 플래그 가져오기만 끄는 `CLAUDE_CODE_DISABLE_FEATURE_FLAGS`도 추가됐다. 이 경우 텔레메트리는 그대로 두고 모든 플래그가 내장 기본값을 쓴다.

관리자용 Claude apps 게이트웨이에도 손이 많이 갔다. 사용 한도가 없는 개발자의 `/usage`에 오늘·이번 주·이번 달 지출이 보이고, 여러 그룹에 속한 개발자의 비용을 어느 그룹 예산에서 먼저 낼지 정하는 `admin.pooled_conflict_rule`, `admin.pooled_priority_order`가 생겼다. 로그인 화면에 운영자 메시지를 띄우는 `login_notice`, JSON 로그를 내는 `CLAUDE_GATEWAY_LOG_FORMAT=json`, 11월 10일 Claude Desktop 변경을 앞둔 정책 경고도 들어갔다.

과금 혼선을 줄이는 장치도 있다. claude.ai 로그인이 끝나 `ant auth login` 로그인으로 넘어가면 Claude Console 조직에 비용이 청구된다는 경고가 뜨고, 시작할 때 청구될 조직 이름을 한 줄로 보여 준다. `/tasks`에는 끝난 서브에이전트를 모은 'Earlier in this session' 줄이 생겨, 재시작한 뒤에도 다시 열어 메시지를 보낼 수 있다.

고친 버그로는 예전 핸드셰이크를 쓰는 MCP 서버가 연결에 실패하거나 빈 결과를 내던 문제, `--resume` 뒤 claude.ai 커넥터의 긴 MCP 호출이 결과를 알리지 않던 문제, 저장소 최상위에 `HEAD`라는 파일이나 폴더가 있으면 `/diff`가 'Diff unavailable'을 띄우던 문제, 64턴 이상 파일을 고친 세션에서 `/diff` 창이 비던 문제, 앞에 공백이 붙은 슬래시 명령이 일반 글로 넘어가던 문제, 401 오류가 다른 세션까지 번지던 문제가 있다.

자세히 보기

클라우드플레어가 코딩 에이전트용 스킬 security-audit-skill을 GitHub에 공개했다. 스킬은 에이전트에게 특정 작업 절차와 지식을 묶어 주는 설명서 겸 도구 모음이다. 저장소 소개에는 '여러 단계로 진행하는 보안 감사, 독립적으로 검증되고 기계가 읽을 수 있는 결과'라고 적혀 있다.

사실 확인 결과 README에는 감사가 6단계로 나뉘고, 취약점을 찾은 에이전트가 아닌 다른 에이전트가 그 결과를 검증한다고 나온다. 결과는 findings.json 파일로 나오며 JSON 스키마로 형식을 검사한다.

이 구조가 눈길을 끄는 이유는 AI 보안 점검의 고질적인 문제인 '그럴듯한 오탐'을 겨냥했기 때문이다. 한 에이전트가 찾고 스스로 맞다고 하면 틀린 보고가 걸러지지 않는다. 찾기와 검증을 나누면 사람이 받아 보는 목록이 줄고 신뢰도가 올라갈 수 있다. 결과가 정해진 JSON 형식이라 CI(지속 통합) 파이프라인이나 이슈 관리 도구에 바로 이어 붙이기도 쉽다.

Claude Code에서 스킬을 쓰는 팀이라면 기존 코드 리뷰 흐름에 보안 감사 단계를 하나 더하는 방식으로 시험해 볼 만하다. 다만 실제 탐지 성능이나 어떤 언어·프레임워크를 잘 다루는지는 입력 자료에 나오지 않는다.

구글이 GitHub에 google/skills 저장소를 열었다. 소개 문구는 '구글 제품과 기술을 위한 에이전트 스킬'이다. 사실 확인 결과 README에는 Google Cloud를 중심으로 한 구글 제품용 스킬 모음이라고 적혀 있다.

에이전트 스킬은 앤트로픽이 Claude에 먼저 들여온 방식으로, 특정 작업의 절차와 참고 자료를 폴더 하나에 묶어 에이전트가 필요할 때 읽게 한다. 플랫폼 회사가 직접 스킬을 내면 에이전트가 낡은 문서나 추측에 기대지 않고 공식 사용법을 따라 작업할 가능성이 커진다.

Claude Code나 다른 코딩 에이전트로 Google Cloud 인프라를 다루는 개발자라면 배포·설정 작업에 넣어 볼 만하다. 이날 클라우드플레어의 보안 감사 스킬, 매트 포콕의 스킬 모음도 함께 화제가 되면서 '스킬'이 도구 회사들의 공식 배포 형식으로 자리 잡는 모습이다. 어떤 스킬이 몇 개 들어 있는지는 입력 자료에 나오지 않는다.
