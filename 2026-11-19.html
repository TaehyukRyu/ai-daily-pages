전날 신문은 로건 킬패트릭(구글 AI Studio 책임자)이 'Gemini' 한 단어만 올리자 새 모델이 나올 것이라는 추측이 돈다는 소식('로건 킬패트릭 'Gemini' 한 단어 게시물 두고 새 모델 출시 추측…확인 안 돼')을 전했다. 그 추측이 하루 만에 맞았다. 구글이 Gemini 4 Neon을 공식 블로그로 발표했다. 킬패트릭은 X에 "Neon은 지능, 속도, 사용 편의성의 균형을 이룬 모델"이라고 쓰고 AI Studio와 API에서 바로 쓸 수 있다고 밝혔다.

Neon은 Gemini 4 가족 가운데 중간 자리다. 가장 무거운 Carbon, 가장 빠른 Hydrogen 사이에 놓인다. 유튜브 리뷰어들은 'Carbon급 성능을 더 싸게 쓰라는 모델'이라고 정리했다.

요금은 공식 글 기준 100만 토큰당 입력 3달러, 출력 15달러다. Carbon의 정가는 12월 1일부터 적용되는 4달러·20달러이므로 Neon이 25% 낮다. 그런데 Carbon은 11월 30일까지 출시 기념가 2달러·10달러를 받고 있다. 이 기간에는 오히려 Carbon이 Neon보다 싸다. 지금 당장 비용을 따진다면 이 점을 함께 봐야 한다. 캐시 입력(이미 보낸 내용을 다시 쓸 때의 입력)은 95% 할인된 0.15달러이고, 컨텍스트(한 번에 넣을 수 있는 분량)는 100만 토큰이다.

쓸 수 있는 곳은 Google AI Studio와 Gemini API 유료 등급, 그리고 Pro·Ultra 구독자의 Gemini 앱과 Antigravity(구글의 에이전트 코딩 도구)다. 구글은 보안 방어 전문가 프로그램인 Fairwind Program의 자격 있는 회원에게 며칠 안에 따로 접근을 연다고 밝혔다.

성능은 구글 발표 기준이다. 사고 수준을 가장 높은 xhigh로 두면 Artificial Analysis 지능 지수에서 61점으로 전체 3위다. 사고 수준은 네 단계이며 기본값은 high다. 기본값 high에서 과제 하나를 끝내는 비용은 Carbon보다 32% 낮았다. 유튜브 채널 영상은 같은 발표를 인용해 Opus 5.5(59점), GPT-6.2 Sol(57점)보다 높고, 터미널 벤치는 65.2%로 Opus 5.5의 65.8%에 조금 못 미친다고 전했다. 경쟁 모델보다 과제당 50~80% 싸다는 것도 구글의 주장이다.

보안 평가도 눈에 띈다. 영상에 따르면 간접 프롬프트 주입(외부 문서·메일에 숨긴 지시로 모델을 조종하려는 공격) 시험 Gray Swan에서 최상위 사고 수준의 공격 성공률이 0%였다. 다른 리뷰어는 이메일 자동화처럼 외부 글을 모델에 넣는 서비스에서는 이 성능이 API 채택 여부를 가른다고 설명했다.

커뮤니티에 퍼진 요약 글에는 '최상위 모델 수준 지능을 3배 빠르고 60% 싸게 제공한다'는 문장이 있다. 이번에 확인한 공식 글에서는 3배·60% 수치를 찾지 못했다. 사실로 받아들이기 어렵다. 리뷰어들도 숫자는 모두 구글 발표 기준이라며 직접 써 본 뒤 다시 평가하겠다고 했다. 한 리뷰어는 늦게 나온 모델일수록 벤치마크에 유리하다며 Neon이 Carbon보다 낫다고 보기는 어렵다고 덧붙였다.

먼저 auto mode가 Amazon Bedrock, Google Cloud의 Agent Platform, Microsoft Foundry, Claude apps gateway에서도 Claude Opus 4.6과 Sonnet 4.6용으로 추가됐다. auto mode는 매번 권한을 묻지 않고 Claude가 판단해 작업을 이어 가는 방식이다. 권한 모드를 따로 정하지 않은 대화형 세션은 이제 이 모드로 시작한다. 회사가 클라우드 계약으로 Claude를 쓰는 경우에도 직접 API를 쓰는 것과 비슷한 흐름으로 일할 수 있게 된 셈이다. 같은 환경에서 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS`를 켜면 auto mode가 매 턴 실패하던 문제도 함께 고쳤다.

훅 쪽에서는 `mcp_tool` 훅에 `"onFailure": "block"` 옵션이 생겼다. 이미 command 훅과 HTTP 훅에 있던 기능으로, 훅 호출 자체가 실패하면 그 동작을 막는다. 보안 검사나 정책 확인을 MCP 도구로 돌리는 팀이라면, 검사 서버가 죽었을 때 검사 없이 그냥 통과하는 일을 막을 수 있다.

운영 관련 경고도 늘었다. 권한 확인을 건너뛰는 세션에서 보낸 메시지가 클라우드 세션에 붙잡혔다가 버려질 수 있으면 경고를 띄운다. OpenTelemetry(사용 지표를 밖으로 보내는 표준) 내보내기에 주소가 없어 데이터가 사라질 것 같으면 `/status`와 `claude doctor`에서 알려 준다. Claude apps gateway에서는 정책의 `maxEffortLevel` 값이 올바른 단계가 아니면 시작할 때 경고한다. `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME`을 쓰면 `claude -p --resume`이나 `--continue`가 훅이 미뤄 둔 도구 호출을 다시 실행하지 않게 할 수 있다.

자체 호스팅 러너(self-hosted runner, 회사 서버에서 Claude Code 세션을 돌리는 기능)에는 `--repository-folder`, 오케스트레이터용 `--hook-label`, `claude --environment`의 `--metadata key=value` 옵션과 대기 시간·포기 횟수 지표가 더해졌다.

버그 수정도 많다. zsh에서 `echo ====`나 `[ a == b ]`처럼 '='로 시작하는 단어가 있으면 'not found' 오류로 멈추던 문제를 고쳤다. 자동 압축(compaction)이 예전 시스템 프롬프트를 그대로 다시 쓰던 문제, 권한 질문 직후 바로 친 Esc가 사라지던 문제, 예약 작업 파일을 읽지 못할 때 다른 예약 작업이 지워지던 문제, 사용 크레딧이 다 떨어졌는데 오류 문구가 속도 제한이라고 나오던 문제도 바로잡았다. 스피너와 서브에이전트의 토큰 수가 재시도된 답을 두 번 세던 문제도 고쳤다.

NVIDIA가 깃허브에 'SkillEvaluator'를 공개했다. AI 에이전트용 스킬과 플러그인을 평가하는 다단계 프레임워크다.
