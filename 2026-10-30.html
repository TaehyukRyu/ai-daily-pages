앤트로픽이 Claude Code v2.1.314를 내놨다. 공식 깃허브 릴리스 노트에 따르면 이번 판의 핵심은 새 설정 `permissions.blockWritesOutsideWorkingDirectories`다. 이 설정을 켜면 Write·Edit·NotebookEdit 도구가 작업 폴더 밖의 경로에 쓰는 요청을 모든 권한 모드에서 거부한다. 권한 확인을 건너뛰는 모드로 돌리더라도 에이전트가 홈 폴더 설정 파일이나 다른 프로젝트를 건드리지 못하게 막을 수 있다는 뜻이다.

VS Code 확장과 Claude Desktop의 Code 탭에는 '유휴 압축(idle compaction)'이 들어갔다. 20만 토큰이 넘는 대화를 한동안 그대로 두면 미리 요약해 두고, 다음 메시지를 보낼 때 프롬프트 캐시(앞서 보낸 내용을 싸게 다시 읽게 해 주는 저장분)가 이미 만료됐다면 그 요약을 쓴다. 긴 대화를 오래 놔뒀다가 다시 이어 갈 때 맥락 전체를 비싸게 다시 읽는 일을 줄이려는 기능이다.

기업용 게이트웨이 쪽에도 기능이 붙었다. Claude apps 게이트웨이의 업스트림(요청을 넘겨받는 모델 제공처)에 `groups` 목록을 달 수 있어, 지정한 IdP(사내 계정 관리 시스템) 그룹의 개발자만 해당 업스트림으로 보낸다. 장애 시 우회 경로에서도 이 규칙이 지켜진다. Bedrock 업스트림에는 어떤 Amazon Bedrock 가드레일 필터가 요청을 걸렀는지 일치한 본문 없이 기록하는 `guardrail_trace`가 추가됐다.

고친 문제도 많다. 조직 관리자가 모델의 추론 강도(effort) 상한을 정해 두면 'Invalid effort level' 오류로 매 턴 실패하던 문제는, 이제 강도를 낮춰 다시 시도하고 어느 단계로 쓰는지 알려 준다. `claude -p`가 시작에 실패해도 아무 출력 없이 종료 코드 0을 내던 버그도 고쳐져 이제 오류를 찍고 1로 끝난다. 스크립트나 CI에서 Claude Code를 부르는 사람에게는 실패를 놓치지 않게 되는 변화다.

훅 사용자가 챙길 항목도 있다. 출력이 아주 큰 PreCompact 훅 때문에 압축이 실패하거나 반복되던 문제를 고치면서, 훅마다 출력을 1만 자에서 자르도록 했다. 또 사용량 한도에서 '자동으로 계속하기'가 /goal 점검이나 백그라운드·예약 작업 때문에 세 번 넘게 이어지던 문제, Ultracode를 꺼도 백그라운드·클라우드 세션이 다음 시작 때 다시 켜던 문제도 바로잡았다.

이 밖에 Bedrock에서 이미지가 많은 세션이 '400 Input is too long'으로 실패하던 문제, Microsoft Foundry에서 기본 모델 배포가 없을 때 실패하던 문제(이제 같은 계열의 이전 모델로 넘어간다), 백그라운드 diff 갱신이 git 인덱스 잠금을 잡아 다른 git 명령이 실패하던 문제 등이 고쳐졌다. 지난 신문에서 다룬 v2.1.312(OIDC 사용자 식별, 큰 CLAUDE.md 덮어쓰기 방지)에 이어 보안·관리 기능을 계속 다듬는 흐름이다.

'코딩 에이전트를 위한 디자인 어휘'를 내세우는 스킬로, polish·bolder 같은 명령으로 디자인 방향을 조정하고 critique·audit으로 검토하며, 'AI 슬롭'(AI가 만든 티가 나는 뻔한 결과물)을 내보내기 전에 잡아내는 탐지기를 README에 소개한다. 지난 신문에서 Impeccable을 다른 디자인 스킬과 비교한 개인 실험을 다룬 바 있는데, 이번에는 저장소 자체가 트렌딩에 올랐다.

thedotmack/claude-mem은 세션이 끝나면 사라지는 맥락 문제를 겨냥한다. 에이전트가 세션 중에 한 일을 모두 기록하고 AI로 압축한 뒤, 이후 세션에 관련 맥락을 다시 넣어 준다. README에 따르면 Claude Code뿐 아니라 OpenClaw, Codex, Gemini, Hermes, Copilot, OpenCode 등을 지원한다.

CopilotKit/OpenBot은 'AI 동료'마다 브라우저·파일·도구를 갖춘 자기 컴퓨터를 주는 오픈소스다. 모든 행동을 실행 전에 결정하고 실행 뒤에 기록한다고 설명하며, AG-UI 규격을 따르는 에이전트라면 무엇이든 연결할 수 있다. milind-soni/OpenMausBot은 봇이 쓸 가상 머신(VM)을 갖춘 오픈소스 Grok Bot 대안으로, README에 클라우드와 로컬 VM을 모두 쓸 수 있다고 적혀 있다.

togg53192-cmd/jailbreaks라는 저장소도 트렌딩에 올랐다. 설명은 'LIST OF ALL MY JAILBREAKS' 한 줄뿐이며, 실제로 어떤 내용이 들어 있는지는 확인되지 않았다. 모델의 안전 장치를 우회하는 프롬프트 모음으로 보이는 이름이지만, 내용을 확인하지 못한 만큼 소개는 이름에 그친다.

정리하면 오늘 트렌딩은 '에이전트에게 기억을, 디자인 기준을, 전용 작업 환경을 붙인다'는 흐름이다. 세션마다 같은 설명을 반복하는 데 지친 사용자라면 claude-mem을, 화면 결과물이 늘 비슷하게 나와 고민이라면 Impeccable을 먼저 살펴볼 만하다.

Claude Code와 Codex를 여러 프로젝트에서 함께 쓰다 보면 창을 일일이 열고 일을 나눠 주는 일 자체가 번거롭다. 코드팩토리 채널이 이 문제를 푸는 터미널 UI(TUI, 글자 화면으로 된 프로그램) Herdr의 사용법을 20여 분짜리 영상으로 정리했다. 제작자는 AI가 다른 에이전트를 띄우고, 작업을 지시하고, 서로 소통하며 일을 배정하도록 꾸려 쓰고 있다고 소개했다.

Herdr 저장소 README에 따르면 이 도구는 화면 분할 패널과 에이전트 상태 표시(작업 중·막힘·대기)를 제공하고, 에이전트가 쓸 수 있는 CLI와 스킬을 함께 둬 에이전트가 직접 다른 에이전트 패널을 띄울 수 있다. SSH로 연결한 원격 머신도 같은 화면에서 다룬다.

영상은 먼저 가벼운 터미널 에뮬레이터 Ghostty를 깔기를 권한다. TUI 자체가 터미널 위에서 돌기 때문에 바탕 터미널 성능이 좋을수록 이득이라는 설명이다. Herdr를 실행하면 왼쪽에 작업공간과 에이전트 탭이 담긴 사이드바, 오른쪽에 메인 화면이 나온다. 탭을 만들고 이름을 바꾼 뒤 한쪽에서 Claude를, 오른쪽으로 화면을 나눠 Codex를 띄우는 식이다. 단축키가 모두 있지만 제작자는 외우기보다 마우스를 쓰거나 AI에게 부탁하라고 권했다.

이어지는 장에서는 git 워크트리(같은 저장소를 여러 폴더로 나눠 동시에 작업하는 기능)로 에이전트마다 작업 공간을 분리하는 법, AI가 다른 에이전트를 실행하는 법, 여러 에이전트를 병렬로 돌리는 법을 다룬다. 후반에는 집에 있는 다른 Mac 같은 원격 컴퓨터를 등록해 로컬과 원격 에이전트를 함께 돌리고, Tailscale(사설 네트워크 도구)로 밖에서도 접속하는 방법까지 보여 준다.

여러 구독 플랜과 여러 컴퓨터를 굴리는 사람에게는 '사람이 창을 관리하는 일'을 에이전트에 넘기는 구체적인 예시다. 다만 영상은 제작자의 작업 방식 소개이며, 생산성이 얼마나 늘었는지를 잰 수치는 없다.

'Spreadsheets are all you need'는 GPT-2의 순전파(입력에서 다음 단어 점수가 나오기까지의 계산)를 표준 스프레드시트 함수만으로 구현한 오픈소스다. README에 따르면 VBA나 매크로는 전혀 쓰지 않는다.

조코딩 채널은 짧은 영상에서 원리를 풀었다. 언어 모델이 하는 일은 다음에 올 단어를 맞히는 것 하나이고, 이를 위해 단어마다 숫자 768개짜리 좌표를 붙여 뜻을 나타낸다. 뜻이 비슷한 단어는 좌표도 가깝다. 단어끼리 서로를 얼마나 참고할지 계산하고 다듬는 과정을 12번 거치면 다음 단어 후보마다 점수가 매겨진다. 결국 모두 곱셈과 덧셈이라 엑셀 칸마다 수식으로 적을 수 있었다는 설명이다.

영상은 들어간 숫자가 1억 2,400만 개, 파일 크기가 1.25GB라고 했지만 README에서는 확인되지 않았다. 실제로 문장을 넣어 돌려 보니 11초 만에 다음 단어를 내놨다고 한다. 실무 도구라기보다 트랜스포머 구조를 눈으로 따라가며 배우기 좋은 교재에 가깝다.

MS·UC버클리 TokenEconomizer…Claude Code 첫 요청 토큰 36% 줄었다는 개인 실측

안 쓰는 도구 정의를 덜어내 짧은 요청의 숨은 토큰 부담을 줄이는 플러그인이다.

파일 하나를 읽고 세 줄로 답하는 짧은 일에도 Claude Code는 첫 요청에 수만 개의 입력 토큰을 싣는다. 도구 정의, 시스템 지침 같은 '짐'이 매번 함께 실리기 때문이다. 코난쌤이 Microsoft와 UC Berkeley가 만든 플러그인 TokenEconomizer를 소개하며 이 문제를 다뤘다.

공식 README에 따르면 TokenEconomizer는 세 가지 기능으로 낭비를 줄인다. 저장소에서 배운 사실을 기억해 두는 '마이크로 스킬', 쓰지 않는 도구 정의를 덜어내는 '툴 프루닝', 같은 실패를 반복할 때 방향 전환을 제안하는 '루프 가드'다. 툴 프루닝과 루프 가드는 기본으로 켜져 있고, 추가 호출이 드는 마이크로 스킬은 기본으로 꺼져 있다. 루프 가드는 제안만 할 뿐 작업을 직접 멈추지는 않는다.

설치에는 Python 3.10 이상이 필요하고 별도 API 키는 필요 없다. README가 밝힌 시험 범위는 Claude Code 2.1.300~2.1.310, Codex 0.153.1~0.164.0이다. GitHub Copilot CLI와 Pi도 지원한다. 영상 제작자는 git 워크트리에서 설정이 원래 저장소에 기록되는 현상을 보고 독립 사본에서 다시 진행했다고 주의를 줬다.

효과 수치는 제작자의 개인 실측이며 공식 자료로 확인된 것은 아니다. 제작자는 Mac M4, Claude Code 2.1.312, Haiku에서 같은 일을 설치 전후 3회씩 돌린 결과, 실린 도구가 56개에서 12개로, 첫 요청 입력 토큰이 51,508개에서 32,980개로 약 36% 줄었다고 했다. 그러나 비용 절감은 3회 평균 9.5%에 그쳤는데, 줄어든 토큰 대부분이 원래 단가가 낮은 캐시 읽기였기 때문이라고 설명했다. 토큰 감소율을 Pro·Max 사용량 한도가 늘어난 비율로 볼 수 없다는 단서도 달았다.

측정 조건에도 한계가 있다. 툴 프루닝 기준을 기본값보다 낮췄고, 가벼운 일 한 종류만 쟀으며, 긴 세션이나 마이크로 스킬·루프 가드의 효과는 재지 않았다. 논문 결과에 따르면 처음에는 오히려 비용이 늘 수 있다고 한다. 함께 올라온 쇼츠에서는 '하늘이 무슨 색이냐'는 한 단어 질문에 Claude Code가 5만 3천 토큰을 보냈다고 했는데, 이것 역시 개인 측정값이다.
